# 닐슨 10원칙 — 시안 평가용

`design-brief` §2(그리기 전 렌즈)와 `design-critique` §1(휴리스틱 평가자)이 읽는다. 발견에는 **`H번호(이름)`**으로 적는다 — `H5`만 쓰지 않는다.

## 10원칙

| # | 이름 | 시안에서 보는 것 | 흔한 위반 |
|---|---|---|---|
| H1 | 상태 보임 | 저장 중·완료·실패, 로딩(스켈레톤/스피너), 진행률이 화면에 있나 | 버튼만 바뀌고 결과 표시 없음 · 조용한 실패 |
| H2 | 현실 언어 | 사용자 말로 쓰였나. 내부 용어·코드값·약어가 없나 | 「Persist」「cp_status=3」 · 사내 시스템 이름 노출 |
| H3 | 통제·탈출 | 취소·닫기·뒤로·되돌리기가 있나 | 모달 닫기 없음 · 확인창만 있고 undo 없음 |
| H4 | 일관성 | 같은 개념에 같은 말·같은 모양·같은 위치인가. 플랫폼 관례를 따르나 | 한 화면은 「편집」, 다른 화면은 「고치기」 · 헤더 위치가 화면마다 다름 |
| H5 | 오류 예방 | 제약 입력(선택지·날짜 선택기), 기본값, 저장 안 된 변경 경고, 위험 동작 분리 | 자유 입력으로 받는 날짜 · 삭제 버튼이 저장 옆에 같은 색 |
| H6 | 기억 대신 알아보기 | 선택지·최근 값·현재 위치가 보이나 | 다른 화면에서 본 ID를 외워 입력 · 필터 상태가 안 보임 |
| H7 | 숙련자 효율 | 일괄 작업·단축키·저장된 필터가 필요한 화면인가 | 100건을 한 건씩 처리 |
| H8 | 미니멀 | 지금 필요한 것만 보이나. 주 행동이 하나인가 | 같은 무게 버튼 4개 · 장식 정보가 데이터보다 큼 |
| H9 | 오류 복구 | 오류 문구가 무엇이·왜·어떻게 고치나 3가지를 말하나. 입력이 보존되나 | 「오류가 발생했습니다」 · 실패 후 폼 초기화 |
| H10 | 도움말 | 처음 보는 개념에 그 자리 설명(툴팁·안내 문구)이 있나 | 용어 설명이 별도 문서에만 있음 |

## 심각도 0~4

빈도(얼마나 자주) · 영향(막히나, 늦어지나) · 지속(한 번인가, 매번인가) 셋을 같이 본다.

| 점수 | 뜻 | 하네스 표기 |
|---|---|---|
| 4 | 과업을 끝낼 수 없다 | 🔴 |
| 3 | 과업이 크게 실패하거나 잘못된 결과를 낸다 | 🔴 |
| 2 | 지연·혼란 | 🟡 |
| 1 | 겉모양 | 🟢 |
| 0 | 취향 차이, 사용성 문제 아님 | 🟢 (기록만) |

## 빠른 진단 10문 (아니오면 발견)

1. 이 화면이 무엇인지 바로 알 수 있나
2. 주 행동이 분명한가
3. 지금 어디에 있는지(내비 활성 표시·제목) 보이나
4. 무슨 일이 일어나는지(로딩·저장·실패) 보이나
5. 오류 문구가 고치는 법을 말하나
6. 되돌리거나 빠져나갈 수 있나
7. 호버 없이도 정보가 다 보이나
8. 아이콘만 있는 버튼에 이름이 있나
9. 대비가 충분한가(본문 4.5:1)
10. 보고 "어?" 하는 지점이 있나

## 원칙끼리 부딪칠 때

| 충돌 | 정리 |
|---|---|
| H8 미니멀 vs H7 효율 | 점진 공개 — 기본은 단순, 숙련 기능은 한 단계 안쪽 |
| H4 일관성 vs 맥락 | 패턴은 같게, 강조만 맥락에 맞게 |
| H7 효율 vs H5 예방 | 확인창보다 undo |
| H10 발견성 vs H8 미니멀 | 주 행동은 보이게, 보조는 숨김 |
