**구현 전에** 시안이 목적·사용성·레퍼런스에 맞는지 평가하고, 고칠 것과 물을 것을 가른다. 승인이 나야 `harness`로 넘어간다.

> `design-reconcile`과 다르다 — critique는 **구현 전, 시안 자체**를 본다. reconcile은 **구현 후, 시안 ↔ 구현 화면**을 대조한다.

## 0. 입력

- 레포 캔버스 소스 `.claude/design/canvas/` — 대상은 **`작업: <기능>` 탭**(현행 탭은 비교 기준으로만)
- `.claude/design/brief.md`(또는 `DESIGN-BRIEF.md`) · `DESIGN.md` · `docs/{feature-YYYY-MM-DD}/PRD.md`의 목적·수용 조건
- 레퍼런스: `.claude/design/references/`(로컬 전용 — 없으면 `README.md`의 URL로 다시 캡처)
- 캔버스 코멘트 스레드 — `ArtifactComments`로 읽는다. 사람이 캔버스에 남긴 피드백도 이번 회차 입력이다
- 회차 단계: 탐색(구성) / 다듬기(시각) / 최종(문구·접근성) — 단계에 맞는 깊이로만 지적한다

## 1. 평가자 — 독립 병렬

서브에이전트로 **동시에** 띄우고, 서로의 결과를 보여주지 않는다(먼저 본 의견에 끌려가지 않게). 각자 같은 입력을 읽는다.

| 평가자 | 보는 것 |
|---|---|
| 디자이너 | 첫인상 2초(시선이 처음 가는 곳이 맞나) · 위계 · 간격·정렬 · DS 일관성 |
| PM / 목적 | PRD 목적·수용 조건과 맞나 · 빠진 화면·상태(스펙 화면 × 상태 목록 대조) |
| 실사용자 walkthrough | 대상 사용자로 주요 과업을 처음부터 끝까지 지나가 본다 |
| UX 라이팅·접근성 | 용어 통일·금칙어·내부 용어 노출 · 대비·터치 영역·키보드 |
| 휴리스틱 | [`references/nielsen-heuristics.md`](references/nielsen-heuristics.md) 10원칙 × 화면. 신규 사용자 → 숙련 사용자 순서로 두 번 순회 |
| 레퍼런스 실측 | 레퍼런스와 같은 축(색·모서리·테두리·타입 단계·그림자·폭)을 **수치로** 잰다. 재기 전에 결론 내지 않는다. 축소 캡처로 재지 않는다 |

페르소나 수는 화면 성격에 맞게 줄여도 된다. 휴리스틱과 PM/목적은 빼지 않는다.

## 2. 발견 표

평가자 결과를 합치고 같은 발견은 한 행으로 묶는다(몇 명이 짚었는지 적는다).

| 화면·상태 | 휴리스틱 | 문제 | 심각도 | 짚은 수 | 근거 보드 | 제안 |
|---|---|---|---|---|---|---|
| 채널 목록·빈 상태 | H1(상태 보임) | 빈 이유가 안 보임 | 3 🔴 | 2 | `ChannelsEmpty` | 「아직 채널이 없어요」 + 새 채널 버튼 |

- 심각도는 0~4, 하네스 표기는 3~4 🔴 · 2 🟡 · 0~1 🟢. 휴리스틱이 아닌 발견(목적·레퍼런스)은 칸에 `목적`·`레퍼런스`라고 적는다.
- **잘 된 점** 3개 이내를 같이 적는다 — 다음 패스에서 지우면 안 되는 것이다.

## 3. 가르기

| 종류 | 처리 |
|---|---|
| 명백한 🔴(정답이 하나) | 바로 고친다 |
| 제품 결정이 필요한 것 | 사람에게 **한 질문씩**, 추천 답과 함께. 회차당 **5개까지** — 넘으면 다음 회차로 미룬다(질문 피로) |
| 레퍼런스와 결정이 부딪치는 것 | A/B를 캔버스에 나란히 그려 고르게 한다 |
| 🟡·🟢 | 모아서 한 번에 고치거나 다음 회차로 |

**고친 것은 캔버스에 as-is | to-be로 나란히 둔다.** 글로만 된 변경 목록은 내지 않는다 — 읽는 사람이 판단하지 못한다.

고친 뒤에는 `design-brief` §5 「그린 뒤」 체크리스트(실렌더 확인 · 원격 반영 확인 · 커밋)를 다시 돈다.

## 4. 체크포인트

회차마다 `.claude/design/checkpoints/NN-<주제>.md` 한 장. 같은 틀을 지킨다:

| 칸 | 내용 |
|---|---|
| 이번에 한 것 | 고친 것 · 새로 그린 것 (캔버스 버전) |
| 보는 법 | 캔버스 URL · 볼 탭 · 볼 순서 |
| 해 보실 것 | 사람이 직접 눌러 볼 과업 2~4개 |
| 제가 정한 것 | 사람에게 묻지 않고 정한 것 — **반려 가능** |
| 아직 안 되는 것 | 남은 🔴·🟡, 다음 회차로 미룬 질문 |
| `verdict:` | 사람이 적는다 — `변경` 또는 `승인` |

결정은 brief의 결정 로그(§결정 로그 · 회차별 절)에 쌓는다. 결정 주체(사람 / AI 추천 수용)를 같이 적는다.

## 5. 다음

- `verdict: 변경` → §3 반영 후 다시 이 스킬.
- `verdict: 승인` → 🙋 → **`harness`**(§3-b가 레포 캔버스를 읽는다).
