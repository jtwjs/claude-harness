# PR 본문 템플릿

`pr-write` 5단계. 레포에 `.github/PULL_REQUEST_TEMPLATE.md`가 없을 때 이 구조로 쓴다.

기본 구조는 `Summary → 전 → 후 → 바뀌지 않은 것 → Risk Score → 변경 유형 → 변경 사항 → 스크린샷(UI 변경일 때, 4.8단계) → 스키마 변경 확인(스키마 변경일 때, 4.95단계) → 모델이 검증한 것 → 사람이 볼 것(👤 항목이 있을 때) → 회고(SDD일 때) → 관련 이슈`. PR 성격에 따라 `변경 사항` 안에 원인/배경·동작 변화·머지 후 후속 작업 섹션을 자유롭게 추가한다. 큰 PR은 `### 1️⃣ … ### 2️⃣ …`로 분리.

```markdown
## Summary

<!-- sdd ⑤ 마무리 세 줄 요약 그대로(형식 정본은 그 절) -->

## 전 → 후

<!-- 고정 칸. 같은 상황 하나를 골라, 이 PR 전과 후에 보이는 것(출력 · 화면 · 동작)을 적는다. 바뀐 줄 목록이 아니라 상황 하나다.
쓸 상황이 없으면(문서만 바꾼 PR 등) 칸을 지우지 않고 `해당 없음: <이유>` 한 줄을 둔다 -->

- 상황: <누가 · 무엇을 할 때>
- 전: <이 PR 전에 보이던 것>
- 후: <이 PR 뒤에 보이는 것>

## 바뀌지 않은 것

<!-- 고정 칸. 이 PR이 건드리지 않아 그대로인 동작 · 범위를 1~3줄. 리뷰어가 「이것도 바뀌었나?」를 다시 묻지 않게 한다.
없으면 칸을 지우지 않고 `해당 없음: <이유>` 한 줄을 둔다 -->

- <그대로인 동작 · 범위>

## ⚠️ Risk Score: <합계>/100 (<낮음|보통|높음|매우 높음>)

<!-- 5축 표 — ${CLAUDE_PLUGIN_ROOT}/skills/pr-write/references/risk-score.md 의 표를 그대로 -->

**리뷰 심각도**: <🔴|🟡|🟢 제안만|없음|미실행> · **자동 머지 조건**: <충족|미충족 — 걸린 쪽> (dry-run, 머지는 사람)

## 변경 유형

- [ ] feat: 신규 기능
- [ ] fix: 버그 수정
- [ ] refactor: 리팩토링 (기능 변경 없음)
- [ ] style: 코드 스타일 변경
- [ ] docs: 문서만 변경
- [ ] chore: 기타 작업

## 변경 사항

<!--
주요 변경 내용을 영역별·우선순위 순으로 작성.
- 사용자 영향이 큰 변경부터 상단에
- 큰 PR이면 ### 소제목으로 분리 (예: 1️⃣ … 2️⃣ …)
- 필요 시 추가: 원인/배경 · 동작 변화(여러 경우의 전/후 표, 대표 상황 하나는 위 「전 → 후」) · 머지 후 후속 작업
-->

## 스크린샷

<!-- UI 변경일 때만(4.8단계). 아니면 이 절을 뺀다. 화면은 이름으로, 이미지는 GitHub 웹에서 드래그 -->

| 화면 | 전 | 후 |
| --- | --- | --- |
| <화면 이름> | <!-- 이미지 드래그 --> | <!-- 이미지 드래그 --> |

## 스키마 변경 확인

<!-- 스키마 변경일 때만(4.95단계). 아니면 이 절을 뺀다. 이유 칸은 작성자 답 그대로, 모르면 ⚠️ 미기록 -->

| 테이블.컬럼 | 변경 | 왜 · 누가 읽나 |
| --- | --- | --- |
| <테이블.컬럼> | <추가·타입 변경·이름 변경·삭제> | <작성자 한 줄> |

- [ ] 마이그레이션 되돌리기 가능 여부 확인

## 모델이 검증한 것

<!-- 실제로 돌린 명령과 결과만. 돌리지 않은 것은 적지 않는다 -->

- `.claude/harness.json`의 `verify` 전체 (build · typecheck · lint · test): <통과|실패 — 무엇>
  <!-- 문서만 바뀐 PR: verify 대신 포맷 검사(예: format:check) 결과를 적고, verify 를 생략했다고 명시 -->
- <돌린 명령>: <결과>

## 사람이 볼 것

<!-- 👤 수용 조건이 있을 때만. 없으면 이 절을 뺀다. sdd-review 「사람이 볼 것」 체크리스트 그대로.
사람이 항목마다 ✅ 로 체크하거나 `건너뜀: <이유(선택)>` 을 줄 끝에 단다. 건너뛰기는 막지 않는다 -->

- [ ] AC-N — <기준 한 구절>

## 회고 (SDD로 진행했을 때)

<!-- sdd ⑤ 마무리: 막힌 지점 → 남긴 자산, `REFLECT 건너뜀: <항목> — <이유>` 줄을 그대로. SDD 밖 작업이면 이 절을 뺀다 -->

## 관련 이슈

<!-- Jira / Linear / GitHub Issue 링크 -->
```
