# No comments

찾고 지우는 쪽은 `comment-hunter` 에이전트, 판정은 메인이다. 에이전트의 새 눈을 따르되 보고를 그대로 믿지 않는다.

## 범위

부른 사람이 준 파일 · diff. 없으면 기준 브랜치 대비 지금 diff(작업 트리 포함). `<base>`는 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/base-branch.sh"` 출력이고, exit 2면 사람에게 묻는다.

## 순서

1. Agent 도구로 `comment-hunter` 에이전트를 부르고 범위를 넘긴다. 에이전트 규칙을 지시문에 다시 적지 않는다 — 두 곳에 쓰면 한쪽만 고쳐진다.
2. 보고와 diff를 판정한다.
   - 거절: 애플리케이션 코드를 고친 것 · 범위 밖을 고친 것 · 예외 목록에 드는 주석을 지운 것 · `MUST KILL` 이유를 잘못 적은 것 · 일부러 남긴 코드를 죄로 모는 표시.
   - 우리 코드의 놀라운 동작에 붙은 고쳐 쓰기 표시는 살린다. 그 주석은 되살리지 않는다. 남기는 주석은 우리가 못 바꾸는 것에 관한 것이라는 증거가 있을 때만 산다.
   - 에이전트가 놓친 범위 안 린트 · TypeScript 억제 주석을 찾는다. 정확성 · 안전을 지키는 규칙의 억제는 `MUST KILL`로 둔다.
   - 지운 주석은 정확한 예외와 범위 안 증거가 있을 때만 되살린다.
   - 근거가 얇은 `IMPORTANT` · `do not remove`를 지우거나 남긴 판정은 받아들이기 전에 그 심볼을 따라가거나, `git log -L` · `git blame`으로 그 줄을 넣은 커밋 · PR · ADR을 찾는다. 지운 것이 애매하면 되살리지 않는다. 남긴 것이 반박되거나 여전히 애매하면 지운다.
   - 거절한 보고는 되돌리고, 무엇이 틀렸는지 짚어 한 번만 다시 돌린다. 두 번째도 거절이면 열린 채로 보고하고 `/no-comments`를 실패로 끝낸다.
3. 받아들인 표시 중 사소한 것은 바로 고친다: 죽은 길 지우기 · 매개변수 빼기 · 진짜 API 쓰기. 모양(이름 바꾸기 · 뽑아내기 · 타입 · 구조)이 필요한 수정이 있으면 받아들인 묶음 전체와 주변 코드를 보고 시그니처 수준 스케치를 한 번만 내고 거기서 멈춘다. 스케치가 설계 결정(회의에서 "왜 이렇게?"를 받을 결정)이면 구현 전에 `${CLAUDE_PLUGIN_ROOT}/docs/principles/ask-questions.md`대로 사람에게 묻는다.
4. 범위 안에서 가장 작은 근본 수정을 구현한다. 이름이 붙은 우회는 모두 걷는다. 근본 원인이 범위 밖이면 범위 안 가장 작은 수정만 하고 나머지는 열린 채로 보고한다. 범위를 넓히지 않고, 증상을 막는 가드를 덧대지 않는다.
5. 제약 주석(`do not remove` · `do not change wording` · `talk to X before changing`)은 따로 다룬다. 우리가 못 바꾸는 것에 관한 것이면 남긴다. 나머지는 범위 안에서 가장 싼 장치(타입 · 런타임 검사 · 테스트 · CI 린트)로 옮기자고 제안하고 사람 승인을 기다린다. 사람이 없는 실행이면 부른 쪽이 미리 승인한 것만 옮긴다. 승인되면 장치로 옮긴 뒤 주석을 지운다. 아니면 주석을 지우고, 그 제약을 열린 채로 보고하고, 범위 밖 할 일을 스케치한다 — 주석으로만 남은 제약은 아무것도 막지 못한다.
