`conductor`가 트랙 세션과 `SendMessage`를 주고받을 때 읽는다. `§N` · 「절 이름」은 `${CLAUDE_PLUGIN_ROOT}/skills/conductor/SKILL.md` 「상황 → 절」 표에서 파일을 찾는다.

## 8. 초인종 — 세션 간 메시지

같은 머신, 같은 계정의 세션끼리는 `SendMessage`로 서로 알릴 수 있다. 이 메시지는 사용자가 세션 사이에서 말을 옮겨 주던 일을 대신한다. 원장은 계속 이슈다.

**세션 이름** — 지휘가 §5 「트랙 세션 열기」로 연 세션은 `-n`으로 이미 이름이 있다. 사람이 연 세션은 시작 때 `/rename`으로 정한다. 이름은 「세션 종류」 표를 따른다(지휘 `conductor` · 옛 사본 지휘 `<레포>-conductor`). 옛 이름으로 보냈는데 그 세션이 없으면 `conductor`로 보내 보고, 그래도 없으면 사용자가 옮긴다. 보내기 전에 `ListAgents`로 이름이 하나뿐인지 본다. 같은 이름이 둘이면 `이름 [ref]`로 보낸다(2026-10-14 실측: 세션 89개 중 같은 이름 2개).

| 언제 | 누가 → 누구 | 본문 |
|---|---|---|
| `follow-up`·`contract-change` 이슈를 열었다 | 지휘 → 담당 트랙 | `#N <라벨> 열림 — <제목>` 한 줄 |
| 결정을 이슈로 옮겼다 | 지휘 → 보고한 트랙 | `#N decision 열림` |
| 지시문 밖 설계 결정이 필요하다 · 예외가 필요하다 · 조사한 코드 사실 | 트랙 → 지휘 | 질문·요청·사실 한 줄. 사용자에게 직접 묻지 않는다. 지휘가 사용자와 정해 이슈로 옮기고 번호로 회신한다(§1) |
| 설계 밖 결정을 정했다(ADR-026 D1) | 트랙 → 지휘 | `#N 댓글 — <결정 한 줄>` 한 줄. 4줄은 이슈 댓글에 있다 |
| 자동 머지 조건을 채운 PR을 머지했다(ADR-026 D2) | 트랙 → 지휘 | `PR #N → <머지 해시>` 한 줄 |
| 트랙 지시문을 넘긴다 | 지휘 → 트랙 | 채운 `track-brief.md`(§5) |
| step·PR을 끝냈다 | 트랙 → 지휘 | track-brief 「끝나면 지휘에 보고」 — 세 줄 요약 · 판정 재료 7줄 · 학습 카드 · 지휘 자리의 지식 저장소로 올릴 것(4칸). 지휘는 4칸을 지휘 자리 쪽으로 넘기고 레포에는 쓰지 않는다(ADR-019 G4) |
| 나눔 모드 · 테스트를 커밋하고 `judge --red`가 통과했다 | 검증 → 구현 (같은 트랙) | `step N red 기록` 한 줄 |
| 나눔 모드 · 구현 `judge`가 끝났다 · 막혀 멈췄다 | 구현 → 검증 (같은 트랙) | `step N 구현 끝` 또는 `step N blocked — <이유 한 줄>` |

- **같은 트랙의 검증 · 구현 세션끼리는 직접 보낸다**(ADR-019 F1). 상태의 정본은 `phases/{task}/index.json`이고 메시지는 차례가 넘어갔다는 알림뿐이라, 다른 트랙이 몰라도 된다. 구현의 blocked는 검증이 한 번 다시 판정하고, 그래도 갈리면 검증이 지휘에 보고하고 지휘가 사용자에게 올린다(ADR-019 E3)
- **다 끝났는지(fan-in) 확인**: 지시문을 보낸 뒤 트랙마다 `notify_when_idle: true`를 한 번 건다. 그러면 트랙이 멈출 때 알림이 한 번 온다. `ListAgents`를 반복 조회하거나 "끝났어?"를 보내지 않는다
- **트랙끼리는 직접 보내지 않는다**(나눔 모드 두 세션은 한 트랙이다). 트랙 A가 트랙 B에만 알리면 트랙 C와 다음 세션은 그 내용을 모른다. 지휘를 거쳐 이슈로 남긴다
- **메시지에 결정 값을 담지 않는다.** 지휘가 보내는 메시지는 이슈 번호와 한 줄만 담는다. 값은 이슈와 ADR에 있다
- **무응답은 동의가 아니다.** 다른 머신, Remote Control, 클라우드 세션은 수신 여부를 알려 주지 않는다. 회신이 없으면 사용자에게 옮겨 달라고 한다
- **권한을 넘기지 않는다.** 내 세션에서 막힌 일, 그리고 §6의 「사용자에게 넘김」에 해당하는 일(운영 DB·배포·비밀값·외부 발송)은 다른 세션에 시키지 않는다. 받은 쪽도 하지 않는다

2026-10-14 실측: 쉬고 있던(idle) 세션이 메시지를 받고 바로 처리해 회신했다. `notify_when_idle` 알림도 보낸 쪽 세션에 도착했다.

**메시지 보류** — 권한 모드가 다른 세션 사이에서는 받는 쪽이 메시지를 붙잡고 사람 승인을 기다린다(2026-11-23 실측: 17건 중 5건 보류 · 1건 만료, 전부 모드가 다른 세션 사이). 10-14 기록(모드가 달라도 승인 창 없이 전달)과 다르게 나왔다. 그래서 지휘 · 작업 세션 모두 `auto`로 맞춘다(§5 `--permission-mode auto`). 보류 알림을 받으면 다시 보내지 말고 사용자에게 무엇이 왜 붙잡혔는지 한 줄 알린다.
