# §5 트랙 지시문 · 트랙 세션 열기 · §6 트랙 예외 승인

`conductor`가 트랙에 일을 맡기고, 트랙이 소유 경로 밖을 요청할 때 읽는다. `§N` · 「절 이름」은 `${CLAUDE_PLUGIN_ROOT}/skills/conductor/SKILL.md` 「상황 → 절」 표에서 파일을 찾는다.

## 5. 트랙 지시문

**보내기 전 관문(§1)**: 결정 이슈 「정할 것」 0 · 설계 문서 확정. 아니면 보내지 않는다.

`.claude/references/track-brief.md`를 채워 트랙 세션에 넘긴다. 손으로 다시 쓰지 않는다. 트랙 세션이 이미 떠 있으면 채운 지시문을 `SendMessage`로 보낸다(§8). 지시문에는 값이 없고 이슈 번호와 `ADR-NNN` 참조만 들어 있으므로 메시지로 보내도 원장이 갈라지지 않는다. 열린 이슈 목록은 §4 조회 결과를 그대로 붙인다.

「도메인 지식 링크(선택)」 칸에는 지휘 자리에 쌓인 그 레포·도메인 문서의 경로만 적는다. 내용을 지시문에 옮기지 않는다. 지휘 자리 문서가 반출 금지 원문이면 링크도 넣지 않는다.

**보내기 전에 겹침을 본다.** 이번 step 범위의 step 파일 「작업」에 적힌 만들/바꿀 파일을 지시문 「바꿀 파일」 칸에 옮기고, §4 현황 표 아래 「겹침」과 다른 트랙에 이미 보낸 지시문의 「바꿀 파일」에 대조한다. 소유 경로가 갈려 있어도 라우트 목록 · enum · DI 모듈 · 공유 타입처럼 기능마다 한 줄씩 느는 파일은 겹친다.

| 겹치면 | 언제 |
|---|---|
| 공유 구역 PR로 먼저 빼서 병합(`tracks.md` §4) | 겹치는 부분이 작고, 두 트랙이 그 위에서 갈라져도 될 때 |
| 순서를 건다(`issues.py block` — 먼저 끝날 쪽 PR 병합 뒤 시작) | 겹치는 부분이 한쪽 작업의 본체일 때 |
| 한 트랙에 몰아준다 | 같은 파일을 계속 같이 고치게 될 때 |

같은 목록형 파일이 두 번 넘게 겹치면 그 파일을 "한 건 = 파일 하나 + 자동 수집" 구조로 바꾸는 `follow-up`을 낸다. 실제로 겹친 파일만이다 — 미리 바꾸지 않는다.

### 새 규칙 → 기존 코드 정리 (ADR-010)

트랙이 새 규칙(린트 · 테스트 · 규칙 파일)을 더하면 새 규칙만 남기고 끝나지 않게 한다. 기존 위반이 그대로면 규칙이 "지금 코드와 다른 말"이 되어 다음 세션이 어느 쪽을 따를지 모른다.

1. **지시문** — 새 규칙이 생길 수 있는 트랙이면 「진행 방식」에 이 한 줄을 넣는다: `새 규칙(린트 · 테스트 · 규칙 파일)을 더했으면 같은 PR 안에서 새 위반을 먼저 막고 → 기존 위반 목록 → 기존 코드 고침 → 0건 출력까지 한다`. 템플릿 「금지」에도 같은 줄이 있다
2. **보고** — 트랙 보고 「판정 재료」 4번에 새 규칙과 남은 위반 건수가 있으면, 0이 아닐 때 지휘가 `follow-up` 「기존 코드 정리: <규칙>」을 낸다(위반 목록 출력 명령을 본문에 붙인다)
3. **소유 경로** — 정리에 소유 경로 밖이 필요하면 §6 「새 규칙 위반 정리만」 판정으로 승인한다. 그 PR에는 위반 정리 외 변경을 섞지 않는다

### 트랙 세션 열기 — 지휘가 직접 (2026-11-01 실측)

지시문이 준비되고 겹침을 봤으면 지휘가 트랙 세션을 연다. 사람이 Orca·터미널에서 열고 `/rename` 하지 않는다.

```bash
git -C <레포> worktree add ../<레포>-<트랙>-<주제> -b feature/<트랙>-<주제> origin/<기준 브랜치>
cd <레포 상위>/<레포>-<트랙>-<주제> && claude --bg --permission-mode auto --effort <역할 값> -n <세션 이름> "<채운 track-brief 본문>"
```

- `--effort`는 늘 넘긴다(ADR-019 C2 · C6). 플래그 없이 띄우면 낮은 effort로 돈다. 레포 설정 `effortLevel`은 폴더 전체에 걸려 역할마다 다르게 줄 수 없다. 값은 ADR-019 E1(역할별) · C7a(세션 하나 모드)에서 읽고 여기 옮겨 적지 않는다
- **나눔 모드**(검증 · 구현 두 세션, `sdd` 「세션 모드 — 나눔 / 하나」)면 worktree 하나 · 브랜치 하나에 세션을 둘 연다(ADR-019 E12). 각자 worktree를 만들지 않는다. 같은 브랜치는 두 worktree에 걸 수 없고, 차례를 알리는 index.json이 한쪽에만 보인다. 차례는 `phases/{task}/index.json`이 정한다

  ```bash
  cd <레포 상위>/<레포>-<트랙>-<주제> && claude --bg --permission-mode auto --effort <검증 역할 값> -n <레포>-<트랙>-verify "<채운 track-brief 본문 — 세션 역할: 검증>"
  cd <레포 상위>/<레포>-<트랙>-<주제> && claude --bg --permission-mode auto --effort <구현 역할 값> -n <레포>-<트랙>-impl "<채운 track-brief 본문 — 세션 역할: 구현>"
  ```

  두 세션에 같은 지시문을 넘기고 「세션 역할」 칸만 다르게 채운다. 구현 세션은 먼저 떠 있어도 러너가 차례가 아니면 거절하므로(종료 3) 검증 세션의 「red 기록」 알림(§8)을 기다린다. FE · BE 기능이면 층마다 따로 연다(ADR-019 E8). 층 사이 계약은 §2 「나눔 모드」 순서를 따른다
- 이름은 「세션 종류」 표를 따른다. 출력 `backgrounded · <id> · <이름>`의 id는 `claude logs`·`attach`·`stop`·`rm`에 쓴다. 나중에는 `claude agents --json`에서 이름으로 찾는다
- 띄운 세션은 `ListAgents`에 `<이름> · bg`로 보인다. 지시·보고는 지금처럼 `SendMessage`(§8)로 하고, 띄운 뒤 `notify_when_idle`을 건다
- `-w`(Claude가 worktree를 만듦)는 쓰지 않는다. 브랜치가 `worktree-<이름>`이 되어 §4 현황의 `feature/<트랙>-…` 매칭에서 빠진다
- 🔴 사용자가 그 레포 폴더에서 Claude를 한 번도 직접 연 적이 없으면 `Workspace not trusted`로 거절된다(2026-11-01 실측: 지휘 자리에서 cd로만 다루던 레포가 거절됨). 사용자에게 `cd <레포> && claude`를 한 번 열어 신뢰를 수락해 달라고 한다. 지휘가 신뢰 설정을 대신 바꾸지 않는다
- 화면이 없다. 세션은 사용자 기본 권한 모드로 돈다(실측: auto). 사람이 보려면 `claude attach <id>`(터미널에서 열기) · `claude logs <id>`(최근 출력)
- **대기 알림**: §4 현황을 볼 때 `ListAgents`에서 트랙이 `waiting`(승인·질문 대기)이면 사용자에게 한 줄로 알린다 — `<이름> 대기 중 · claude attach <id>`. 화면이 없어서 지휘가 알리지 않으면 아무도 모른다

## 6. 트랙 예외 승인

트랙 세션이 소유 경로 밖을 고쳐야 한다고 보고하면 **지휘가 판정한다.** 트랙은 사용자보다 지휘에게 먼저 `SendMessage`로 묻는다. 사용자에게는 아래 표의 「사용자에게 넘김」만 간다(2026-10-01~08 실측: 예외 12건이 전부 사용자에게 몰렸다).

| 판정 | 언제 |
|---|---|
| 승인 — 그 트랙 PR에 포함 | 한두 줄 · 다른 트랙이 지금 안 만지는 파일(예: 픽스처 한 줄) |
| 승인 — 새 규칙 위반 정리만 | 그 트랙이 더한 새 규칙의 기존 위반을 고치는 변경이고, 다른 트랙이 지금 안 만지는 파일(§5 「새 규칙 → 기존 코드 정리」) |
| 공유 구역 PR로 분리 | 여러 트랙이 받아 갈 변경 |
| 소유 트랙에 `follow-up` 발행 | 소유 트랙이 지금 그 파일을 만지는 중 |
| **사용자에게 넘김** | 비가역(운영 DB·배포) · 보안(비밀값·권한) · 외부 부작용(메시지 발송·과금) |

판정은 해당 이슈에 코멘트로 남긴다: `판정: <승인|분리|후속 #N|사용자> — <이유 한 줄>`. 이슈가 없으면 `follow-up` 이슈를 만들고 거기에 남긴다.
