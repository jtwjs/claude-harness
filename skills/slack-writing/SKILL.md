# /slack-writing: 슬랙 메시지 작성

**한 줄**: 상대가 다시 찾아보지 않아도 되게 쓴다. 결론이 먼저, 사실은 짧게, 요청은 한 문장.

**절대 하지 않을 것**: 사용자가 준 적 없는 근거·수치·사실을 지어내지 않는다. 없으면 `⚠️ 근거 필요`로 표시하고 묻는다. 실명은 쓰지 않고 역할로 부른다. 파일로 저장할지, 어디에 저장할지는 사용자에게 먼저 묻는다.

## 절차

1. **유형 판별**: 공유 / 요청 / 회신 / 결과 보고 / 공지 / 불가 응답 / 지적·이견 중 하나. 초안만으로 못 가리면 묻는다. 채널에 이미 정해진 포맷(예약봇·팀 템플릿)이 있으면 그 포맷이 뼈대이고 이 스킬은 안에 무엇을 적을지만 정한다. 새 형식을 만들지 않는다
2. **결론 끌어올리기**: 하고 싶은 말을 다 적은 뒤 결론 문장을 찾아 맨 위로 옮긴다. 요청이면 "상대가 뭘 해주면 되는지"가 결론보다도 앞
3. **그릇 설계**: 아래 표
4. **유형별 골격** 적용
5. **문장 규칙** 적용
6. **지우기 패스**: 해석 문장 → em dash → 볼드 → 인사·예고 문장 순으로 지운다
7. **체크리스트** 통과
8. **출력**: 아래 형식

## 공통 규칙 (문서와 같음)

- 구조 4단: ①결론 한 문장 ②근거·현황(숫자·사실) ③판단 근거(내 해석임을 드러냄) ④다음 액션(내가 할 것 / 상대의 결정)
- 확신도는 어미로 표시한다. 확실한 것만 `~입니다`, 모르는 것은 그 부분만 잘라 `~는 모르겠습니다`, 추정 기한은 `(아마 내일..)`. 필수와 있으면 좋음을 구분한다
- 톤: 사실·현황은 음슴체 불릿, 사람에게 하는 말·요청은 호명 + 해요체. "부탁드림"은 무례하게 읽힌다
- em dash 0. 장식 이모지 0. 볼드는 메시지당 1줄
- 해석 문장을 지운다. 판별법: 앞 불릿을 지우면 이 문장도 성립하지 않으면 그건 해석이다. 연결은 읽는 사람이 한다
- 열린 질문은 제안값 + 확인 요청으로 바꾼다. 제안값은 본문에 이미 적은 논리에서만 끌어낸다

## 그릇 설계 (메시지 밖의 구조)

| 상황 | 규칙 |
|---|---|
| 채널에 올릴 때 | 최상위는 `[대상] 유형: 제목 >>` 한 줄. 본문은 스레드 첫 댓글. 채널 스크롤이 목차가 된다 |
| 항목이 3개 이상 | 한 메시지에 몰지 않고 항목당 메시지 1개. 항목별로 리액션·반박이 달릴 수 있게 |
| 문의·요청을 받았을 때 | 접수("확인하겠습니다")를 2분 안에, 결과는 별도 메시지로. 두 번 나눠 보낸다 |
| 구두로 끝난 논의 | 끝난 직후 채널에 라벨 + `w/@참석자` + 결과 불릿. 액션 아이템은 별도 메시지에 담당 + 판단 기준 + 막히면 갈 곳 |
| 멘션 | 본문에 섞지 않고 맨 끝 `cc.` |
| 개발자·비개발자가 같이 있는 채널 | 같은 변경을 청중별 두 메시지로 |

## 유형별 골격

| 유형 | 첫 줄 | 골격 |
|---|---|---|
| 공유(진행) | 상태 한 문장. 반복 공유는 문장 없이 `과업 → 세부 → 상태 이모지` 3단 | 분모(목표 대비 어디) · 기준 기간 · 착지 예상이 같이 있어야 판단이 된다. 활동량은 단독으로 쓰지 않고 퍼널 안에. 긴 보고는 끝에 `Net:` 3문장 |
| 요청 | 요청 자체(`[요청]` 태그) | 이유 블록(무엇을 하려는지) → 요구 조건과 기한만(수단을 지정하면 그 수단마다 "왜?"가 돌아온다) → 마지막에 "무엇을 회신하면 되는지" 한 줄 → 나올 질문 1~2개를 `Q. / A.`로 미리 |
| 회신 | 상대의 번호·제목을 그대로 복사 | `->` 뒤에만 결과. 안 한 것은 안 했다고 쓰고 이유·시점은 괄호. 검증 못 한 것은 "안 되면 알려주세요" |
| 결과 보고 | 결론을 소제목으로("결론부터 말씀드리면" 허용) | 사전 가설 중 틀린 것을 내가 먼저 지목 → 숫자를 "그래서 무엇을 얼마나"로 번역 → 성립 안 한 구간을 밝히고 재실행 조건 → 판단을 넘길 땐 "왜 내가 정하면 안 되는지" 한 줄. 근거가 비공식이면 비공식이라고 |
| 공지(남의 행동 제약) | 제목에 시간 범위 | 내용 → 안전장치 → 협조 요청(볼드 1줄 + 이유 괄호) → 결과 예고. 안전장치가 없으면 "그거 안전해요?"가 반드시 돌아온다. 나쁜 소식은 결론 먼저 + 괄호로 톤 규정("질책 아님") + 과잉 반응을 막는 문장 하나 |
| 불가 응답 | "어렵습니다" + 숫자 근거 | 바로 `대신` → 검토 중인 것 → 그때까지의 우회로. 상대 표현을 따옴표로 되받는다. 끝에 제안 자체에 감사 |
| 지적·이견 | 주어를 나로(`저는 여기서 ~라고 생각했어요`) | 겪은 순간을 따옴표로 재현 → 약한 부정 → 판단 기준 2개를 주고 결정은 상대에게 → 내가 할 몫 한 줄로 닫기 |

## 문장 (구구절절과 AI 티를 막는 것은 여기다)

- 불릿당 한 줄. 서술어는 명사형이나 `~음`으로 끊는다. 접속사 없이 병렬로 놓는다
- 제목은 명사구. "~에 대해 공유드립니다", "확인 부탁드립니다" 같은 인사·예고 문장은 쓰지 않는다
- 본문 문장은 결론만. 디테일·유보·예외는 괄호로 민다
- 배경은 상대가 모르는 것만. 상대가 아는 맥락을 다시 설명하지 않는다
- 숫자는 비율을 병기한다(`12곳(3.9%)`). 표에는 숫자만, 문장에는 해석만
- 한계는 `다만`으로 시작해 앞의 결론을 지우지 않는다
- 부정은 약하게(`덜 띕니다`, `~하지 않음`). `틀렸다` 같은 단정은 쓰지 않는다. 체감이면 `저는 ~느껴지더라고요`로 주관임을 표시
- 딱딱하게 읽히면 문장을 늘리지 말고 어미 한 글자만 바꾼다
- 사과는 한 문장("제 설명이 부족했습니다")에 곧바로 재요청 한 문장. 사과가 길면 재요청이 눈치 보는 것처럼 읽힌다
- 완료 보고는 "안 되면 다시 알려주세요"로 닫는다. 요청 문턱은 부사로 낮춘다(편하게, 언제든)
- 정체는 형용사 대신 숫자(`34일째 업데이트 없음`)
- 이모지는 상태 코드 세트(진행중 / 완료 / 주의)와 문장 끝 감정 1개로 분리. 정상 상황에 ⚠️나 "오류"를 쓰지 않는다. 축하는 문장 대신 이모지
- 남이 준 정보로 고쳤으면 누가 줬는지 쓴다

## AI 티

| 냄새 | 고치는 법 |
|---|---|
| `**현상.** / **요청.**` 볼드 라벨 뒤 마침표 | 라벨을 걷고 문장으로 |
| 모든 메시지가 같은 3블록 | 유형마다 필요한 만큼만 |
| "말씀드리자면", "정리하자면", "안녕하세요" 도입부 | 삭제. 첫 줄이 결론 |
| `##` 헤더, `> 참고:` 인용 블록 | 슬랙에서는 불릿과 볼드 1줄로 |
| 같은 말 세 번(배경 + 불릿 + 부연) | 한 번 |
| 문단 끝 요약 문장("즉, ~가 중요합니다") | 삭제 |
| "~하도록 하겠습니다", "~해 주시면 감사하겠습니다" 반복 | 한 번만, 또는 "~할게요" |

## 보내기 전 체크

- [ ] 첫 문장이 결론 또는 요청인가
- [ ] 근거를 물으면 내 말로 설명할 수 있나. 아니면 어미로 확신도를 표시했나
- [ ] 마지막에 "무엇을 하면 되는지"가 있나
- [ ] (요청) 요청이 결론보다 앞에 있고, 수단 대신 조건과 기한을 적었나
- [ ] 항목 3개 이상을 한 메시지에 몰지 않았나
- [ ] (회신) 상대의 번호를 그대로 미러링했나
- [ ] (지적) 주어가 나이고 내가 할 몫이 붙어 있나
- [ ] (거절) 우회로를 같이 줬나
- [ ] (결과 보고) 틀린 가설과 성립 안 한 구간을 내가 밝혔나
- [ ] (과제 던질 때) 나올 질문을 `Q. / A.`로 미리 박았나
- [ ] 인사·예고 문장이 0인가
- [ ] 두 줄 넘는 불릿이 없나

## 출력 형식

초안이 있었으면 Before를 위에 그대로 두고 After를 아래에.

```
### 채널 최상위 (1줄)
[대상] 유형: 제목 >>

### 스레드 본문
(항목 3개 이상이면 --- 로 메시지 경계를 표시)

### 적용한 규범 (요청 시 3~5줄)
```
