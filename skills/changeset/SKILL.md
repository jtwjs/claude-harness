git 변경사항을 분석해서 Changeset 파일을 자동으로 작성해줘.

## 1단계: 변경 내용 수집

아래를 순서대로 실행해서 변경 내용을 파악한다:

```bash
git log main..HEAD --oneline           # 현재 브랜치 커밋 목록
git diff HEAD --stat                   # 변경 파일 목록과 규모
git diff HEAD -- apps/<app>/     # creator-ms 실제 diff
git diff HEAD -- packages/             # packages 변경(diff)
```

diff가 없으면 `git diff --cached --stat` 로 staged 변경도 확인한다.
변경된 주요 파일은 Read 도구로 내용을 직접 읽어 컨텍스트를 보강한다.

## 2단계: Changeset 필요 여부 판단

| 변경 내용                         | 필요 여부 | bump       |
| --------------------------------- | --------- | ---------- |
| 새 기능·페이지·주요 컴포넌트 추가 | ✅        | `minor`    |
| 버그 수정·UI 개선·성능·리팩토링   | ✅        | `patch`    |
| API 구조 변경·브레이킹 체인지     | ✅        | `major`    |
| 테스트·문서·CI·스타일만 변경      | ❌        | 생성 안 함 |

**불필요한 경우**: 이유를 설명하고 종료한다.

## 3단계: slug 추론

브랜치명을 사용하지 않는다.  
**커밋 메시지와 변경된 파일·코드 내용을 분석**해 변경을 가장 잘 표현하는 2~3단어 영문 레이블을 만든다.

규칙:

- 형식: `{동사}-{도메인}` 또는 `{동사}-{도메인}-{상세}` (kebab-case, 소문자)
- 동사 후보: `add`, `fix`, `update`, `remove`, `improve`, `refactor`
- 도메인은 변경된 feature/entity 이름 기반 (`article`, `tag`, `publish`, `channel`, `image` 등)
- 2단어가 충분히 명확하면 3단어로 늘리지 않는다

예시:
| 변경 내용 | slug |
|---|---|
| 기사 복제 기능 추가 | `add-article-copy` |
| 태그 10개 초과 에러 수정 | `fix-tag-limit` |
| 발행 설정 유효성 개선 | `improve-publish-validation` |
| 채널 변경 시 카테고리 초기화 | `fix-channel-category-reset` |
| 기사 목록 페이지네이션 추가 | `add-article-pagination` |

## 4단계: 파일 생성

**경로**: `.changeset/{slug}.md`

**형식**:

```
---
"참고레포A": {patch|minor|major}
---

{한국어 요약 1~3문장}
```

### 대상 패키지 정책

- **`참고레포A`는 Changeset으로 관리한다.** 사용자 영향이 있는 `feat/fix/refactor` 변경이면 changeset을 생성한다.
- `packages/*`(예: `내부 DS 패키지`)에 사용자 영향 변경이 있으면 해당 패키지도 changeset을 생성한다.
- `.changeset/config.json`의 `ignore` 패키지는 changeset 대상에서 제외한다.

**요약 작성 기준**:

- 커밋 메시지 복붙 금지 — diff 기반으로 새로 서술
- "무엇이 바뀌었는지" + "사용자·팀원에게 어떤 의미인지" 포함
- 좋은 예: "기사 케밥 메뉴에 '복제해서 새 기사 작성' 기능 추가. 현재 기사의 제목·본문을 복사해 새 기사를 시작할 수 있습니다."
- 나쁜 예: "기사 복제 기능" (너무 짧고 컨텍스트 없음)
- **patch 요약은 맨 앞에 분류 마커를 단다** — 개선이면 `개선:`, 버그 수정이면 `수정:`로 시작한다. 릴리즈 시 가이드 업데이트 내역이 이 마커로 **개선 / 수정(버그)** 섹션을 자동 분류한다(마커 없으면 기본 `수정(버그)`). `minor`·`major`는 마커 불필요(항상 "새 기능"). 예: `수정: 보도기사 목록에서 작성중 기사가 발행완료로 잘못 표시되던 문제 수정`, `개선: 목록에서 제목 수정 시 포털 제목까지 함께 반영`.

### 이 요약은 그대로 사용자에게 노출된다 — 사용자 언어로 쓸 것 (필수)

changeset 요약은 `CHANGELOG.md`를 거쳐 **사용자 가이드 [업데이트 내역](../../../docs-app/src/app/release-notes/page.mdx)에 문구 변경 없이 실린다.** L1(`docs-app/scripts/sync-release-notes.mjs`)은 공백·분류 마커만 정리할 뿐 **다시 쓰지 않는다.** 따라서 여기 쓴 표현이 곧 실무자가 읽는 릴리즈 노트다 — [docs-app/CLAUDE.md](../../../docs-app/CLAUDE.md)의 "사용자 언어만" 원칙이 **changeset 요약에도 그대로 적용**된다.

**쓰지 말 것** (릴리즈 노트에 새어 나간 실적 있음 — v0.25.1에서 사후 정정):

| 부류               | 예시                                                | 대신                                                  |
| ------------------ | --------------------------------------------------- | ----------------------------------------------------- |
| role enum          | `USER`·`ADMIN`·`SUPER_ADMIN`·`GUEST`                | 프리랜서/인턴 · 팀원 · 팀 관리자/시니어 · 최고 관리자 |
| scope 번호·필드    | `scope 8`·`scope_id`                                | 보도기사 권한 · 포토기자 권한 (권한 이름)             |
| API·엔드포인트     | `channel-get`·`POST /article/list`·`article_title`  | 언급하지 않는다 — 사용자가 겪는 증상·결과만           |
| 내부 경로          | `/manage/members`                                   | 화면 이름(팀원 관리)                                  |
| 컴포넌트 구현 용어 | 모달 · 드로어 · 리스트뷰 · 그리드뷰 · 스켈레톤 · 폼 | 화면 · 창 · 목록형 보기 · 갤러리형 보기 · 안내        |
| 구현 수치·스펙     | `127px`·`staleTime`·`z-index`                       | 눈에 보이는 결과("크기를 맞췄습니다")                 |

**예** — 같은 변경, 다른 표기:

- ❌ `수정: 인스타 수집처 수정 화면이 channel-edit로 조회해 프리필이 안 되던 문제 수정. channel-get으로 교정.`
- ✅ `수정: 인스타 수집 설정에서 수집처 수정 화면을 열 때 기존 정보가 채워지지 않던 문제를 수정했습니다. 이제 계정 유형·계정·표시 이름·카테고리·페르소나 값을 정상적으로 불러옵니다.`

**첫 문장이 굵은 제목이 된다** — L1의 `splitLeadAndRest`가 첫 문장(`…다.`/`…요.`)을 `- **제목**`으로, 나머지를 `— 설명`으로 가른다. 첫 문장은 **한 줄로 짧게** 끊고 상세는 두 번째 문장부터 쓴다. 첫 문장에 부연을 다 넣으면 제목이 통째로 굵어져 읽기 어렵다.

## 5단계: 결과 출력

```
파일: .changeset/{slug}.md
bump: patch | minor | major
slug 근거: {커밋/diff에서 어떤 내용을 읽고 추론했는지 한 줄}
이유: {bump 선택 근거 한 줄}
```

생성 후 커밋하지 않는다. 개발자가 내용을 확인한 뒤 `/commit` 커맨드로 함께 커밋하도록 안내한다.
