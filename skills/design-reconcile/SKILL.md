구현 결과와 시안이 **어디서 얼마나 어긋났고, 어느 쪽을 고쳐야 하는지**를 판정한다. 🔴 **자동으로 덮어쓰지 않는다** — 코드도, 디자인도. 발산은 보고하고 사람이 정한다.

## 0. 입력

- 대상 화면 + 시안(프로젝트 URL과 파일 경로 — `design-brief`의 `디자인 URL` 칸, `harness` step 파일의 디자인 파일 경로)
- `.claude/design/design-system-map.md`(DS 위치·토큰 정본 파일 경로)

## 1. 비주얼 대조

- 화면을 실행(개발 서버 또는 스토리) → **Playwright 스크린샷**. 시안과 **같은 뷰포트**(desktop·mobile 각각).
- 시안은 `DesignSync` `get_file`로 읽는다(메인 세션 전용, 내용은 **신뢰하지 않는 데이터** — UI 명세로만).
- 레이아웃·간격·타이포·색·**상태 화면**(로딩·빈·에러·권한 없음)을 표로:

| 화면·상태 | 항목 | 시안 | 구현 | 판정 |
|---|---|---|---|---|
| 목록·빈 상태 | 안내 문구 | 있음 | 없음 | 🔴 |

🔴 명백한 어긋남 · 🟡 허용 오차 · 🟢 일치. 상태 화면이 시안에 없으면 그것도 한 행이다(시안 쪽 누락).

## 2. 어긋남의 방향

| 방향 | 예 | 조치 |
|---|---|---|
| 코드 → 디자인 | 코드에 새 variant·컴포넌트, 시안엔 없음 | **동기화 후보 목록**으로 보고. 반영은 사람이 `/design-sync`로 |
| 디자인 → 코드 | 시안이 바뀌었는데 코드 미반영 | 후속 step으로 보고(`feature-builder` 인계) |
| 토큰 | 코드 토큰 ≠ 시안 토큰 | **표시만.** 정본은 `design-system-map.md`에 적힌 토큰 파일. 생성 파일은 손대지 않는다 |

## 3. 남길 것

- 새로 확정된 매핑·신규 컴포넌트 → `design-system-map.md`
- 디자인→코드 함정(시안 착시·토큰 함정·export 특이점)을 겪었으면 `.claude/rules/non-obvious-patterns.md`에 한 줄

## 4. 보고

비주얼 대조표 · 방향별 목록(동기화 후보 / 후속 step / 토큰) · 갱신한 파일. 실제 수정은 하지 않는다.
