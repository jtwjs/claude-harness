PRD를 **디자인 브리프**로 압축하고, 그 브리프로 **레포에 묶인 캔버스**에 시안을 그린다. 앱 코드는 만지지 않는다(문서·캔버스 산출 전용).

> **시안을 그리기 전에 결정을 끝내는 것이 이 스킬의 값이다.** 권한·상태·데이터가 정해지지 않은 채 그린 시안은 정상 화면 한 장만 예쁘고, 빈 화면·에러·권한 없음은 구현 때 추측으로 채워진다.

## 0. 입력

- `docs/{feature-YYYY-MM-DD}/PRD.md`. 없거나 모호하면 `sdd` ① 계획 DESIGN(`references/design.md`)으로 먼저 만든다.

## 0.5 레퍼런스 먼저

브리프보다 **스타일 베이스와 레퍼런스를 먼저** 정한다. 브리프를 쓴 뒤 톤을 바꾸면 브리프와 `DESIGN.md`를 다시 쓴다(2026-10 두 레포 모두 그랬다).

- 레퍼런스 사이트·화면을 사람과 정하고 원본 크기로 캡처해 `.claude/design/references/`에 둔다. **커밋하지 않는다** — 로컬 전용(남의 화면·용량). 커밋하는 것은 `references/README.md`(출처 URL · 캡처 목록 · 찍은 날짜)뿐이고, 다른 머신에서는 README를 보고 다시 캡처한다
- 레퍼런스에서 가져올 것 / 가져오지 않을 것을 한 줄씩 적는다

## 1. 로드 (이 파일들만)

- 루트 `CLAUDE.md` · 대상 `PRD.md`
- `.claude/design/design-system-map.md` — 레포의 디자인 시스템(컴포넌트 패키지·토큰 파일 경로·기존 매핑). 없으면 레포에서 DS 위치를 찾아 이 파일을 만들자고 제안한다
- 이미 있으면 `.claude/design/DESIGN.md`(스타일 정본)
- 이미 있으면 `.claude/design/canvas/canvas.json`(레포 캔버스 — `현행` 탭이 지금 화면이다)

## 2. 시안 전에 끝낼 결정 — 한 번에 한 질문

레포(코드·PRD·기존 화면)에서 답이 나오는 것은 **스스로 찾는다.** 남은 **제품 결정만** 한 번에 하나씩, 추천 답과 함께 묻는다(`why` 「질문 규칙」).

| 칸 | 묻는 것 |
|---|---|
| 권한 | 역할·세부 권한별로 보이는 것/비활성인 것. 특정 권한 전용 화면인가 |
| 상태 | 로딩(스켈레톤/스피너) · 빈 · 에러(개별/전역) · 비활성 · 긴 텍스트 각각 무엇을 보여주나 |
| 데이터 | 출처(API·쿼리) · 페이지네이션(서버/클라) · 실시간 여부 · 낙관적 업데이트 |
| 폼 | 필수·검증 규칙 · 에러 위치(인라인/토스트) · 제출 비활성 조건 |
| 반응형 | 데스크톱↔모바일 전환 규칙 · 모바일 전용 구성 |
| 인터랙션 | 모달·드로어 닫기 · 포커스 · 키보드 · 모션 |
| 기존 기능과의 관계 | 교체 / 확장 / 신규 — 보존해야 할 기존 동작 |

**닐슨 렌즈** — 위 칸을 채운 뒤, 화면마다 넷이 답해졌는지 본다. 비면 그 칸의 질문으로 돌아간다. 10원칙 전체는 [`design-critique/references/nielsen-heuristics.md`](../design-critique/references/nielsen-heuristics.md).

- H1(상태 보임) — 로딩·저장·완료·실패가 화면마다 정해졌나 → 「상태」 칸
- H3(통제·탈출) — 취소·닫기·되돌리기가 정해졌나 → 「인터랙션」 칸
- H5(오류 예방) — 제약 입력·기본값·위험 동작 분리가 정해졌나 → 「폼」 칸
- H9(오류 복구) — 오류 문구가 무엇이·왜·어떻게를 말하고 입력이 보존되나 → 「상태」·「폼」 칸

## 3. 산출물 — `.claude/design/`

**레포에 디자인 시스템이 있느냐로 형태가 갈린다.**

| 상황 | 만드는 것 | 왜 |
|---|---|---|
| **DS가 있다** | `DESIGN-BRIEF.md` 1장 | 스타일은 정해져 있다. 시안은 실제 컴포넌트·토큰으로 그려진다 — 브리프는 결정과 재사용 후보를 짚는다 |
| **DS가 없다**(그린필드) | `brief.md`(내용) + `DESIGN.md`(스타일) 2장 | 토큰부터 정해야 한다. 내용과 스타일을 나눠야 톤 교체 실험이 성립한다 |

2장으로 갈 때는 **`brief.md`에 색·서체·치수를 쓰지 않고, `DESIGN.md`에 화면 이름을 쓰지 않는다.** `DESIGN.md`는 백지에서 쓰지 않는다 — 좋은 시스템을 복제하고 **바꾼 것만** 적는다. 토큰만 적으면 절반짜리다 — **Principles · States · Motion을 문장으로** 적는다.

### 브리프 구성

| 섹션 | 내용 |
|---|---|
| 화면 목적 | 한 문장 + 대상 사용자·진입 경로 |
| 화면/뷰포트 | 화면 목록, mobile/desktop |
| 권한 · 상태 · 데이터 · 폼 · 반응형 · 인터랙션 | §2에서 정한 답. **상태는 화면 단위로** 적는다 — `/design`이 상태별 화면을 실제로 그리게 |
| 재사용 후보 | `design-system-map.md`의 컴포넌트를 **코드 이름으로**(`ArticleCard`, "저 카드" 말고). 확정 아님 |
| 제약 | 토큰·a11y·i18n·반응형·성능 |
| 비목표 | 이번에 다루지 않는 것 |
| 디자인 URL | 캔버스 URL + 회차별 캔버스 버전 기록 — §5에서 되적는다 |
| 결정 로그 | 회차별 절. 결정 · 이유 · 결정 주체(사람 / AI 추천 수용). `design-critique`가 이어 쓴다 |

## 4. 캔버스 — 레포당 하나, 레포에 묶는다

시안 · 디자인 시스템 · 컴포넌트를 **캔버스 하나의 탭**으로 관리한다. 캔버스는 Artifact Design 타입(`Artifact` `action: "quickstart"`, `intent: "design"`)이고 `canvas.json`의 `pages`가 탭, `boards`의 `page`가 보드의 탭이다. DS를 별도 아티팩트로 두지 않는다.

| 탭 | 담는 것 |
|---|---|
| `현행` | 지금 구현돼 있는 화면 전부 — `design-reconcile`의 기준점 |
| `작업: <기능>` | 이번 기능 몫만. **변경**은 현행 보드를 복사해 as-is \| to-be로 나란히, **추가**는 새 보드 |
| `디자인 시스템` | 토큰 · 색 · 타입 · 간격 |
| `컴포넌트` | 컴포넌트 보드. 코드 이름 매핑은 `design-system-map.md` |

DS·컴포넌트 탭을 이번 기능이 바꿀 때도 as-is | to-be로 둔다. 작업 탭을 현행에 반영하는 것은 `design-reconcile` 통과 뒤다(그 스킬 §3).

- **정본은 레포**: 캔버스 소스를 `.claude/design/canvas/`(`canvas.json` · `*.dc.html`)에 커밋하고 **거기서 발행한다**. 캔버스 URL은 브리프 `디자인 URL`에 적는다. 레포에 캔버스가 이미 있으면 새로 만들지 않고 작업 탭을 추가한다
- **발행 전에 원격 `canvas.json`을 읽어 머지한다** — 사람이 캔버스 페이지에서 보드를 옮기거나 메모를 달면 원격이 바뀐다. 읽지 않고 덮으면 그 수정이 사라진다
- **발행 1회 = 커밋 1개.** 커밋 메시지와 브리프 `디자인 URL`에 캔버스 버전을 적는다
- 작업 탭 두 개가 같은 현행 보드를 바꾸면 머지 순서대로 현행에 반영하고, 뒤에 반영하는 쪽은 현행 기준으로 as-is를 다시 뜬다

## 5. 시안 제작 체크리스트

🙋 **브리프(+ `DESIGN.md`) 승인 전에는 그리지 않는다.** 승인 뒤에는 Claude가 캔버스를 만든다(`/design` 또는 Artifact Design 타입). 이미지 레퍼런스를 여러 장 붙여야 하면 claude.ai/design도 된다. 스타일 파일은 **한 번에 하나만** 넘긴다 — 둘을 같이 던지면 톤이 섞인다.

**그리기 전**

- [ ] 스펙 화면 × 상태(정상·로딩·빈·에러·권한 없음) 목록을 뽑아 보드 목록으로 쓴다 — 빠진 화면이 리뷰에서야 나왔다(「빠진 부분없이」「상세화면은 없어?」)
- [ ] 탭을 정한다 — 작업 탭 이름, 현행에서 복사해 올 보드
- [ ] 구성이 갈리는 화면만 저충실 A/B로 먼저 고르게 한다 — 전 화면 A/B는 하지 않는다
- [ ] 컴포넌트를 코드 이름으로 부른다(`ArticleCard`, "저 카드" 말고)

**그린 뒤**

- [ ] **캔버스 실렌더를 직접 본다** — 브라우저로 캔버스 URL을 열어 탭마다 확인한다. 로컬 Chromium 렌더로 대신하지 않는다(중첩 import·웹폰트가 다르게 나온다). 발행만 하고 "확인했다"고 쓰지 않는다
- [ ] **원격 반영을 확인한다** — `Artifact` `action: "list"`, `scope: "files"`로 이번에 바꾼 파일이 다 올라갔는지 본다(경로 실수로 두 패스가 통째로 안 올라간 적이 있다)
- [ ] 빈·로딩·실패·엣지 상태가 실제 보드로 있다 — 적어 둔 것과 그려 본 것은 다르다
- [ ] `.claude/design/canvas/` 커밋 + 브리프 `디자인 URL`에 캔버스 버전
