PRD를 **디자인 브리프**로 압축해 Claude Design에 넘길 입력을 만든다. 코드는 만지지 않는다(문서 산출 전용).

## 0. 입력

- `docs/{feature-YYYY-MM-DD}/PRD.md`. 없거나 모호하면 **추측 말고 질문**.

## 1. 로드 (이 파일들만)

- 루트 `CLAUDE.md` · 대상 `PRD.md`.
- `.claude/design/design-system-map.md`(재사용 후보 탐색용. 구 경로 `.claude/process/design-system-map.md`도 본다).
- 이미 있으면 `.claude/design/DESIGN.md`(스타일 정본).
- ⚠️ 그 외 docs 미열람(컨텍스트 절약).

## 2. 산출물 — `.claude/design/`

**레포에 디자인 시스템이 있느냐로 형태가 갈린다.** 먼저 판별한다.

| 상황 | 만드는 것 | 왜 |
|---|---|---|
| **DS가 이미 있다** (내부 DS 패키지·토큰 파일 존재) | `DESIGN-BRIEF.md` 1장 | 스타일은 이미 정해져 있다. 브리프는 **재사용 후보**를 짚는 일이 전부다 |
| **DS가 없다** (그린필드 UI) | `brief.md`(내용) + `DESIGN.md`(스타일) 2장 | 토큰부터 정해야 한다. 내용과 스타일을 나눠야 톤 교체 실험이 성립한다 |

2장으로 갈 때는 **`brief.md`에 색·서체·치수를 쓰지 않고, `DESIGN.md`에 화면 이름을 쓰지 않는다.**
합쳐 두면 톤을 바꿀 때 내용까지 흔들려 무엇 때문에 나아졌는지 설명할 수 없다.
`DESIGN.md`는 백지에서 쓰지 않는다 — 좋은 시스템을 복제하고 **바꾼 것만** 적는다.
토큰만 적으면 절반짜리다. **Principles · States · Motion을 문장으로** 적어야 빈 화면·로딩·실패에서 흔들리지 않는다.

### `DESIGN-BRIEF.md` (또는 `brief.md`) 구성

| 섹션              | 내용                                                                                                |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| 화면 목적         | 한 문장 + 대상 사용자·진입 경로                                                                     |
| 화면/뷰포트       | 화면 목록, mobile/desktop 여부                                                                      |
| 상태              | **loading · empty · error · edge**(빈 데이터·긴 텍스트·권한없음) 각각 무엇을 보여줄지               |
| 재사용 후보       | `.claude/design/design-system-map.md`·`내부 DS 패키지`에서 맞을 법한 컴포넌트를 bullet(확정 아님, 힌트용) |
| 제약              | 토큰(색/타이포는 `theme.css` 기준)·a11y·i18n·반응형·성능 제약                                       |
| 비목표            | 이번 디자인에서 다루지 않는 것                                                                      |
| Claude Design URL | **작성 시엔 빈칸.** 사람이 디자인 생성 후 알려주는 프로젝트 링크를 되적는다(자동 아님) — §3         |

## 3. 마무리 (DESIGN 루프: 브리프 → 시안 생성 → URL 회수)

- **브리프 작성 시 `Claude Design URL` 칸은 비워둔다**(플레이스홀더). 이 시점엔 시안이 없어 URL도 없다.
- 브리프를 사용자에게 보여주고 **시안 생성을 개시하도록 안내한다.** 경로는 둘이다:

  | 경로 | 언제 |
  |---|---|
  | **`/design`** — Claude Code 내장 캔버스 | 기본. 세션을 떠나지 않아 결정 맥락이 이어진다 |
  | **claude.ai/design** — 웹 캔버스 | 이미지 레퍼런스를 여러 장 붙이거나 인라인 편집·슬라이더로 다듬을 때 |

  ⚠️ **어느 쪽이든 사람이 개시한다.** 이 스킬은 브리프까지만 만들고 화면을 뽑지 않는다.
  ⚠️ 브리프와 스타일 파일을 **함께** 넘기되 **스타일 파일은 한 번에 하나만** — 두 개를 같이 던지면 톤이 섞인다.
- 생성이 끝나면 **사용자가 프로젝트 URL을 알려주고**, 그 값을 브리프의 `Claude Design URL` 칸에 되적는다.
  ⚠️ **자동으로 붙지 않는다** — `DesignSync`는 디자인 파일 **읽기/푸시**용이지 이 로컬 브리프에 URL을 심어주지 않는다.
- **넘기기 전 3가지**(핸드오프 품질은 넘기는 순간이 아니라 그 앞에서 결정된다):
  ① 컴포넌트를 이름으로 부른다("저 카드" 말고 `MeetupCard`) ② 결정을 바꾼 이유를 채팅에 남긴다
  ③ **빈·로딩·실패·엣지 상태를 실제 화면으로 뽑아본다** — 적어두는 것과 그려보는 것은 다른 일이다
- 다음: **`design-plan` 스킬** — 그 URL의 `projectId`로 DesignSync를 호출해 디자인 파일을 읽고
  요소↔컴포넌트 매핑을 확정한다.
