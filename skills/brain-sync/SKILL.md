**지식이 프로젝트에 갇히는 것을 막는다.** `_brain/`을 깔수록 각 레포에 지식이 고이므로, 통합 wiki로 흘려보내야 축적이 된다.

> 부수 효과가 하나 더 있다 — **배출구가 있으면 프로젝트의 `_brain/wiki/`가 계속 가벼워진다.** 어떤 레포는 배출구가 없어 33파일 72KB까지 자랐고, 그게 매 세션 로드됐다.

## 0. 대상 확인 (필수)

`.claude/harness.json`의 `brainSync`를 읽는다:

```json
"brainSync": { "wikiPath": "…", "targetFolder": "wiki/projects/<name>" }
```

없으면 **묻는다** — ① 통합 wiki 경로 ② 어느 폴더에 넣을지. 답을 `harness.json`에 캐시한다. **경로를 추측하지 않는다.**

## 1. 🔴 민감 정보 거부

- `_brain/internal/`은 **이관하지 않는다.** 스킬이 거부한다.
- 자격증명·토큰·개인정보·고객 식별 정보가 보이면 **그 항목을 빼고** 무엇을 뺐는지 보고한다.
- ⚠️ **통합 wiki가 조직 밖(개인 계정 등)에 있다면**, 조직 고유 정보(조직명·내부 도메인·사내 규칙)를 그대로 옮기는 것은 **조직 정보를 조직 밖으로 옮기는 것**이다. 이관 전에 그 사실을 한 줄 경고한다.

## 2. 무엇을 옮기나

**옮긴다**: 도메인 용어·비즈니스 흐름·아키텍처 결정(왜 그렇게 했나)·제품 맥락·고객 피드백에서 얻은 판단.

**옮기지 않는다**: 코드를 읽으면 아는 것 · git 이력으로 복원되는 것 · 그 레포에서만 의미 있는 파일 경로 · 이미 통합 wiki에 있는 것(**중복 확인 먼저**).

## 3. 12살 이해법 — 한 파일 안에 두 층

각 페이지에 정식 서술을 쓰고, 그 아래 절을 붙인다:

```markdown
## 쉽게 말하면 (12살 기준)
```

전문 용어를 빼고, 비유를 쓰고, **왜 이게 필요한지부터** 쓴다.

> 이 절을 못 쓰겠다면 **아직 이해한 게 아니다.** 그 자체가 신호다.

## 4. 절차

1. `_brain/wiki/`를 읽고 **통합 wiki에 이미 있는지** 확인한다(중복 방지)
2. 옮길 항목을 목록으로 만들어 **🙋 사람에게 보여주고 확인받는다**
3. `targetFolder`에 쓴다 — `_brain/wiki/`의 카테고리 구조를 유지
4. **원본은 남긴다**(복사이지 이동이 아니다). 정리는 `_brain/CLAUDE.md`의 archive 규칙이 담당
5. 통합 wiki의 인덱스·로그를 갱신한다(그쪽 규약을 따른다)
6. 이관한 항목 수와 **뺀 것**을 보고한다

## 5. 폴더 이름 충돌 주의

통합 wiki에 이력서용 `work/projects/` 같은 폴더가 이미 있으면, 이 스킬이 쓰는 `wiki/projects/`와 **역할이 다르다**(전자는 경력 기술, 후자는 도메인 지식). 양쪽 인덱스에 **서로를 가리키는 한 줄**을 남긴다.

## 금지

- 사람 확인 없이 이관하지 않는다
- 원본을 지우지 않는다
- 통합 wiki의 기존 문서를 **덮어쓰지 않는다** — 같은 주제가 있으면 병합안을 제시하고 묻는다
