## 작업

- `design.md`의 「**설계서 틀**」 문단 첫 줄(「**설계서 틀**」로 시작하는 줄)은 그 글자로 시작하게 둔다. 문단 내용은 새 틀에 맞게 고친다: 사람이 읽기 쉽게 칸 아래 불렛으로 쓴다 · 우선순위 단계(반드시 · 가능하면)는 두지 않는다(「목표와 비목표」 두 칸으로 충분하다) · 아주 자세히 3칸은 디스패치 전에는 제목만 두고 구현 전에 채운다
- 그 문단 바로 아래 첫 ```` ```markdown ```` 코드 블록을 아래 제목 줄로 바꾼다. 제목 글자 · 급(`##` / `###`) · 순서가 계약이다(step 2 칸 순서 검사가 이 블록을 읽는다). 각 `###` 줄 끝에 `←` 뒤 한 줄 안내를 단다. `##` 줄의 안내는 선택
  ```
  # <기능> 설계 문서
  ## 간단히
  ### 1. 한 줄 요약
  ### 2. 문제
  ### 3. 전체 구조
  ### 4. 고른 안과 버린 안
  ### 5. 트레이드오프
  ### 우리 칸
  ## 자세히
  ### 6. 목표와 비목표
  ### 7. 대안 비교
  ### 8. 상황별 동작
  ### 9. 열린 질문과 누가 정하나
  ## 아주 자세히
  ### 10. 상세 설계
  ### 11. 공통 관심사
  ### 12. 배포와 롤백
  ```
- 안내 문구 재료(원본 포맷 칸 뜻, 문장은 다듬어도 된다): 한 줄 요약 — 무엇을, 동사가 상태다(제안했다 · 정했다 · 접었다) / 문제 — 지금 겪는 장면 하나 / 전체 구조 — 그림(mermaid), 정한 뒤의 흐름 · 큰 구조 상자 3~5개 / 고른 안과 버린 안 — 다섯까지, 안마다 이유 한 줄 · 결정 주체 / 트레이드오프 — 하나씩, 좋은 것만 적지 않는다 / 목표와 비목표 — 목표와, 할 수도 있었지만 뺀 것 + 뺀 이유 / 대안 비교 — 위 안들을 같은 기준으로 재는 표 / 상황별 동작 — 표: 이럴 때 · 이렇게 / 열린 질문과 누가 정하나 — 번호 질문 + 추천 · 정할 사람 / 상세 설계 — 데이터 · API · 순서를 실제 이름으로 / 공통 관심사 — 보안 · 개인정보 · 운영 · 비용 / 배포와 롤백 — 배포 순서와 되돌리는 법
- 옛 틀에만 있던 안내를 옮긴다(빠지면 그 규칙이 사라진다): 옛 「수용 기준」의 「위험 큰 기능(돈 · 데이터 손실 · 동시 요청 · 권한)만 Given · When · Then」 → 「상황별 동작」 안내에 / 옛 「비기능 요구사항」의 「숫자로. 모르면 가정으로」 → 「공통 관심사」 안내에 / 옛 「제약」(요청에서 받은 전제 그대로) · 「가정」(확인 안 한 전제 · 수치 + 확인 방법) → 「우리 칸」 안내에, 「사람이 볼 것」(👤 기준 한 구절)과 함께
- 공개 레포다. 틀 · 안내 · 예시에 사람 · 회사 이름 · 개인 경로 · 개인 기록 문구를 넣지 않는다
- 이 step은 틀 문단과 코드 블록만 바꾼다. 같은 파일의 설계서 순서 · 화면 · 설계서와 세 장 · 끝 · Readiness · 설계문서 3장 절은 step 3이 바꾼다
