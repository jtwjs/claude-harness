# ADR — 하네스 점검 2단계 (checkup-design 트랙)

> 번호는 지휘(`conductor`)가 발급한다. 결정 원문은 jtwjs/claude-harness 이슈 #47(본문 + 댓글 4개). 이번 범위는 설계 · 계획까지이고 구현은 사용자 승인 뒤에 한다.

## ADR-018 하네스를 덜어낼지는 있음 / 없음 점수 차이로 정한다

- 상태: 수락 (2026-11-25)
- 맥락: 모델이 좋아지면 하네스가 할 일은 줄어든다. 지금은 무엇을 덜어낼지를 감으로 정한다. `claude plugin eval --ablation with-without`(2.1.332)는 같은 과제를 플러그인이 있는 쪽과 없는 쪽(기본 Claude)으로 돌려 점수 차이(Δ)를 낸다. 이 레포에는 아직 `evals/`가 없다. 사용 기록(최근 호출 수)은 판정 근거로 쓰지 않는다 — 기록 기간이 실제 작업량을 대표하지 못할 수 있다(#47 A).
- 판정 흐름: 있음 > 없음 → 유지 · 있음 ≈ 없음 → 덜기 후보 · 있음 < 없음 → 먼저 덜기. 마지막 판정은 사람이 한다.

### A5 실측 — 전역 설정 섞임 (2026-11-25, CLI 2.1.332)

- 방법: 빈 스크래치 플러그인에 case 1개를 두고 `claude plugin eval . --ablation with-without --runs 1 --max-cost-usd 1 --keep-temp`. 도구 없이 「출력 스타일 이름 · 스킬 접두별 개수 · 사용자 전역 CLAUDE.md 첫 제목 · `claude-harness:` 스킬」을 답하게 하고, 두 쪽 trace의 init 이벤트와 답을 봤다. 비용 $0.19(2회 합)
- 결과(두 쪽 같음):
  - 실행 폴더와 HOME이 실행마다 새 임시 폴더다(`/private/tmp/e-*/home/cwd`). 끝나면 home · tmp를 봉인한다
  - 출력 스타일: `default`. 사용자 출력 스타일이 안 들어온다
  - 사용자 전역 CLAUDE.md: 없음
  - 사용자가 설치한 플러그인(이 플러그인의 설치본 포함): 없음. 기본 내장 플러그인 3개만 두 쪽 모두 로드됐다
  - 시험 대상 플러그인은 있음 쪽에만 로드됐다
- 뜻하는 것: eval의 Δ는 「기본 Claude 대비 이 플러그인」이다. 사용자 전역 지시와 하네스 규칙이 겹치는지(이미 전역에 있는 규칙을 하네스가 또 말하는지)는 eval로는 안 보인다 → A5 선택지

### 시험 결과

- 방법: `claude plugin eval . --eval-dir docs/harness-checkup-2026-11-25/evals --ablation with-without --runs 3 -j 4 --max-cost-usd 4`(대상 = 이 레포 플러그인, 모델 기본 opus, LLM 채점기 haiku). case 3개: `sdd-vague-feature`(떠야 함, 요구사항부터 정하나) · `why-challenge`(떠야 함, 근거를 따지나) · `rename-no-skill`(안 떠야 함, 짧게 답하나)
- 결과:

| case | 있음 점수 | 없음 점수 | Δ | 있음 비용 · 턴 | 없음 비용 · 턴 |
|---|---|---|---|---|---|
| `sdd-vague-feature` | 1/3 | 3/3 | −0.67 | $0.604 · 5~6턴 | $0.219 · 2턴 |
| `why-challenge` | 2/3 | 3/3 | −0.33 | $0.504 · 6~7턴 | $0.224 · 1턴 |
| `rename-no-skill` | 3/3 | 3/3 | 0 | $0.210 · 1턴 | $0.136 · 1턴 |

  - 합계 $1.90(18회, 상한 $4 안). 있음 쪽이 회당 약 2.5배 비싸고(턴 · 스킬 본문 · 참조 읽기), 두 쪽 모두 오류 없이 돌았다
  - 이 Δ는 덜기 근거가 아니다 — 셋 다 시험 설계 탓으로 설명된다:
    1. `sdd` 있음 쪽 3회 중 2회가 `max_turns: 4`에 걸려 답을 못 냈다(스킬이 참조 파일을 읽는 턴이 든다). 턴 상한이 하네스 쪽만 깎았다
    2. `why` 있음 쪽 실패 1회는 답 내용이 통과한 두 회와 같은 형태인데 haiku 채점기 3표가 FAIL 2 · PASS 1로 갈렸다 — 채점기 흔들림
    3. 채점 기준이 쉬웠다 — 없음 쪽(기본 opus)이 이미 9/9 통과. 기본 모델도 하는 행동을 물으면 Δ는 0 이하로만 나온다
- 설계에 넣을 것(phases 「eval 틀」 step의 AC):
  - case `max_turns`는 하네스 쪽이 스킬 · 참조를 읽고도 답할 만큼(시험값 4 → 12 이상) 두고, 턴 상한에 걸린 실행은 점수 대신 「무효」로 센다
  - 채점은 기본 모델이 안 하는 하네스 고유 결과로 고른다(예: 질문을 한 번에 하나 · 추천 표시 · 결정 기록 파일 · 세 줄 요약) — 결과(outcome) 채점기 우선, `tool_used: Skill`은 표시용
  - LLM 채점기는 판정이 갈리는 case에 `--judge-model`을 올리거나 regex · file_exists로 바꾼다
  - 비용: 회당 있음 ~$0.15 · 없음 ~$0.06(이 시험). case 20개 × 3회 × 2쪽이면 약 $13 → 점검 1회 상한 `--max-cost-usd 20` [추정, 시험 1회 기준]
- 대가: eval은 「기본 Claude 대비」만 본다(A5). 사용자 전역 지시와 겹치는 규칙, 실제 레포 맥락에서의 값은 A2 ② · A5 ②가 따로 본다
