## ADR-023 구현 시작 관문과 재판정 진입점을 러너에 둔다

- 상태: 결정 (2026-11-26). R1 · R2 · R3 모두 사용자(AI 추천 수용)
- 갱신: ADR-019 E3 — 「검증이 한 번 다시 판정」 뒤에 「테스트가 틀렸다」면 검증이 테스트를 고쳐 커밋하고 `rejudge`로 구현 차례로 넘긴다(R3)는 절차가 붙는다. 「구현은 테스트 파일을 못 고친다」 · 「그래도 갈리면 사용자」는 그대로
- 맥락: ADR-022 D6 3번은 구현 시작(계획 쪼개기 포함)을 「정할 것」 0일 때만 하게 했다. 글 규칙만이면 ADR-014가 고친 「다 정하기 전 구현」이 다시 난다. 지휘 쪽 근거: 글 규칙이 있는데도 설계 질문을 채팅으로 낸 사례가 같은 날 있었다(사용자 방향 「규칙보다 린트 · 훅 같은 장치」). 나눔 모드(ADR-019)에서 재판정이 「테스트가 틀렸다」면 러너에 길이 없어 사람이 `red` · BASE · `wip` 커밋을 손으로 정리한다(#77 재현, `docs/sdd-runner.md:58`)
- ADR 조건(`skills/sdd/references/design.md:49-52`): 되돌리기 비싸다(러너 계약을 두 세션 · 지휘 문서가 같이 쓴다) · 코드만 보면 무엇을 왜 세는지 모른다 · 버린 방법이 있다

### R1 관문이 세는 것

- 읽는 곳: `start`는 `index.json`의 `docs` 폴더, `gate`는 인자로 받은 폴더. 그 안의 `ADR.md` · `PRD.md`만 본다(설계서는 레포 밖이라 읽지 않는다)
- ADR: 제목(`#` 몇 개든)에 「결정할 것」이 든 절의 표. 머리줄에서 「주체」가 든 칸을 찾고, 그 칸이 빈 행을 연다고 센다. 「주체」 칸이 없는 「결정할 것」 표는 모든 행을 연다고 센다(기본이 멈춤)
- PRD: 「남은 ⚠️」가 든 제목 줄(아래 다음 같은 급 제목까지) 또는 불렛 라벨 줄(`- **남은 ⚠️**`, 그보다 깊게 들여 쓴 줄까지) 아래의 첫 단 불렛 항목. `→ 결정:` 또는 `막지 않음:`이 든 줄은 뺀다. 「없음」으로 시작하는 항목은 항목 없음 표시라 뺀다(리뷰 1회차)
- 열린 것이 있으면 멈추고(종료 2, 사람 필요) 「ADR R1: <정할 것>」 · 「PRD: <항목>」 꼴로 하나씩 보인다. 폴더 · 파일이 없으면 막지 않는다(한 줄 안내, AC-2)
- 버린 방법: A ADR 표만(PRD ⚠️가 글 규칙에 남는다) / B PRD는 `⚠️ 미결정` 표지 줄만(쓰는 쪽이 표지를 잊으면 샌다 — 이 트랙 PRD도 표지 없이 썼다)
- 대가: 이 결정 뒤 PRD 「남은 ⚠️」는 결정이 나면 줄 끝에 `→ 결정: <ADR 번호>`를 단다(뜻은 바꾸지 않는다). 막지 않는 메모도 `막지 않음: <이유>`를 달아야 통과한다

### R2 관문 위치

- `sdd_runner.py gate <docs 폴더>`(종료 0 통과 · 2 열림)를 `sdd-plan` §0이 폴더를 정한 직후 부른다. `start`는 같은 검사를 부작용(브랜치 · exclude 쓰기) 전에 돈다. 헤드리스 `run`은 `start`를 거친다(`sdd_runner.py:832`)
- 버린 방법: A `start`만(계획 쪼개기는 막지 못한다) / B `sdd-plan`만(스킬 문장이라 건너뛸 수 있다)
- 대가: `sdd-plan`의 부르기는 모델이 지키는 문장이다. 건너뛰면 계획은 쓰이지만 `start`에서 멈춘다

### R3 재판정 진입점

- 부르는 때: 검증 세션이 재판정(E3)해 「테스트가 틀렸다」로 보고, 테스트 파일만 고쳐 커밋한 뒤
- 차례: 끝나지 않은 첫 step이 그 step이고 blocked이며 `red`가 있을 때만. 아니면 아무것도 안 바꾸고 종료 3(ADR-019 E12와 같은 장치). 커밋 안 된 변경이 있으면 종료 1
- 확인: ① HEAD 쪽 끝의 커밋들(구현 · `wip` 커밋 뒤)이 테스트 파일(과 `phases/`)만 담았고, 옛 `red`와 테스트 파일 내용이 다르다 ② 그 고친 테스트를 BASE(구현 전) 트리에 얹어 `verify.test`를 돌리면 실패한다 — 「테스트를 약하게 고쳐 통과」를 막는다. 어긋나면 아무것도 안 바꾸고 종료 1
- 기록: `red` = 고친 테스트 커밋(HEAD), status pending, `blocked_reason` · `blocked_at` 지움, BASE 그대로, `rejudged`에 `{at, red_before}` 한 줄, index 커밋. 구현 커밋은 브랜치에 그대로 남는다
- 두 번째 막힘: 이미 `rejudged`가 있는 step이 다시 blocked면 `rejudge`는 거부하고 종료 2 — E3 「한 번 다시 판정, 그래도 갈리면 사용자」
- 구현 쪽 판정 5: `rejudged`가 있는 step은 「BASE 뒤 구현 변경(테스트 · `phases/` 밖 파일)이 있나」로 본다. 테스트만 틀렸고 구현이 이미 맞으면 구현 세션은 더 고칠 것이 없어서다. 판정 4(새 `red` 뒤 테스트 파일 무변경)는 그대로
- 「구현이 고칠 일」로 재판정했으면 지금처럼 status를 pending으로 되돌린다(`red` 유지, 진입점 없음 — 이번 범위 밖)
- 버린 방법: #77 후보 1 상태만 pending(`red` 그대로 — 구현 쪽 판정 4가 고친 테스트를 되돌린다, `sdd_runner.py:519-530`) / #77 후보 2 BASE 다시 고정 + `red` 지우고 `judge --red`(구현이 이미 고친 테스트를 통과시키면 RED 「아무것도 안 잡음」 → 새 BASE로 reset되어 고친 테스트가 `sdd-discard/`로 밀린다, `:683-691` · `:713-722`)
- 대가: 러너에 하위 명령이 하나 늘고 index.json step에 선택 칸 `rejudged`가 생긴다(status 값 4개는 그대로)

### 결과

- 관문이 장치로 서므로 Readiness 6(`design.md:69`)의 「막는 ⚠️ 0」은 러너가 다시 확인한다
- 장치로 못 막는 갈래: ADR이 「결정할 것」 표 없이 옛 ADR 블록 꼴로만 쓰였거나 결정이 ARCHITECTURE 한 줄로만 남은 경우, 열린 결정을 셀 칸이 없어 통과한다. `docs/sdd-runner.md`에 글 한 줄 + 이유로 남긴다
