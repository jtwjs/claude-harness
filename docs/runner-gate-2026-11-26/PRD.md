# PRD — runner-gate

> 원문: https://github.com/jtwjs/claude-harness/issues/83 본문 「PRD」 칸(지휘 작성). 아래는 고치지 않고 옮긴 것이다. 「남은 ⚠️」 줄 끝의 `→ 결정:`만 결정 뒤 더했다(ADR-023 R1). 같이 닫는 이슈: #77

## 원문 PRD (나눔 모드 첫 실전 — 지휘 작성, ADR-019 E4)
- **무엇을**: 러너(`sdd_runner.py`)에 길 두 개를 넣는다. ① 구현 시작 관문 — 열린 「정할 것」이 있으면 계획 · 구현 시작을 멈춘다 ② 재판정 「테스트가 틀렸다」 뒤 진행 길 — 구현과 고친 테스트를 잃지 않고 다음 차례로 간다(#77)
- **왜**: ① 「다 정하기 전에 구현부터」(ADR-014가 고친 것)는 글 규칙만으로 다시 생긴다. 그래서 장치로 건다(ADR-022 D6 3번) ② 지금은 재판정 뒤 두 길이 다 막혀서 사람이 손으로 정리한다(#77 재현)
- **성공지표**: 미측정 — 방법: 다음 나눔 모드 트랙들에서 「정할 것이 남은 채 시작」 건수 · 재판정 뒤 손 정리 건수 / 기한: 다음 나눔 모드 트랙 3개
- **사용자 시나리오**
  1. 검증 세션이 계획을 시작하는데 ADR 초안에 열린 「정할 것」이 2개다 → 러너가 멈추고 열린 항목을 보여 준다 → 지휘가 결정 묶음으로 사람에게 묻는다 → 0개가 되면 통과한다
  2. 구현이 막혀 검증 세션이 다시 판정한다 → 「테스트가 틀렸다」 → 검증 세션이 테스트를 고치고 진입점 하나로 구현 차례로 넘긴다 → 구현 커밋과 고친 테스트가 둘 다 남는다
- **범위**
  - 포함: 위 두 길 · 러너 단위 테스트 · `docs/sdd-runner.md` 나눔 모드 절 · `sdd-run` 안의 진입점 안내 한 줄
  - 하지 않을 것: 설계서(레포 밖) 읽기 · #82가 고치는 지휘 · 설계 문서 흐름 · 세션 하나 모드 동작 변경
- **수용 조건** (맡는 쪽: 전부 검증 세션이 테스트로 쓰고 구현 세션이 통과. 👤 없음)
  - AC-1 열린 「정할 것」이 있는 임시 레포에서 관문이 멈추고(0이 아닌 종료 + 열린 항목 목록), 0이면 통과한다 — 단위 테스트
  - AC-2 레포에 ADR 초안이 없는 작은 일은 관문이 막지 않는다. 장치로 못 막는 그 갈래는 문서에 글 한 줄 + 이유
  - AC-3 재판정 「테스트가 틀렸다」 뒤 진입점 하나로, 구현 커밋 · 고친 테스트를 잃지 않고 다음 차례로 간다 — 스크래치 레포 걷기 + 단위 테스트
  - AC-4 `bash hooks/test.sh` · 러너 단위 테스트 통과
- **남은 ⚠️** (계획 때 검증 세션이 조사해서, 결정 묶음으로 지휘에 올린다)
