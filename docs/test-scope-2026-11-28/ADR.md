## ADR-025 전체 테스트는 PR CI에서 한 번, 로컬은 바꾼 부분만 돈다

- 상태: 결정 (2026-11-28). S1~S5 사용자(AI 추천 수용). 열린 결정 0
- 맥락: 한 줄 문서를 고쳐도 전체 테스트가 돌고, 한 작업에서 여러 번 돈다. 리뷰는 2회차부터 diff만 대조하면서도 「verify는 늘 전체로」 돈다(`skills/sdd-review/SKILL.md:19` · `:29`). 트랙 지시문은 완료 조건을 verify 출력으로, 보고를 실제로 돌린 검증 출력으로 둔다(`templates/.claude/references/track-brief.md:14` · `:62`). 그래서 리뷰 지적을 고칠 때마다 전체가 다시 돈다. 이 레포 실측: 업그레이드 공통 규칙 갱신 작업이 로컬 전체 2번(263초 · 262초) + CI 5분 16초, references 한 줄 안내 작업이 로컬 전체 1번(301초) + CI 4분 14초(지휘 확인, 세션 기록 시각)
- 이미 있는 장치: verify(앱별이면 앱마다)의 `"$step": {"test": "… {since} …"}`. 러너는 판정 3(red) · 판정 6 · 지시문 검증 명령 · 헤드리스 Stop 훅에서 전체 명령 대신 이것을 쓰고, `{since}`에 그 step 시작 커밋을 채운다(`skills/sdd-run/scripts/sdd_runner.py:388-399` · `hooks/validate-session-end.sh:60-66`). 템플릿 주석에도 예시가 있다(`templates/.claude/harness.json:29`). 전례: 0.31.1에서 Stop 훅이 응답마다 전체 테스트를 돌리던 것을 뺐다(36회 · 35.9분)
- ADR 조건(`skills/sdd/references/design.md` 「끝」 3번): 되돌리기 비싸다(깔린 레포 harness.json 계약) · 코드만 보면 왜 로컬에서 전체를 안 도는지 모른다 · 버린 방법이 있다

### S1 전체는 PR CI에서 한 번

- 로컬에서 테스트를 도는 자리는 셋이다: 작업 중 확인, 리뷰 「빌드·테스트」 축(회차마다), 러너 step 판정. 셋 다 `$step.test`가 있으면 그것을 돈다
- 전체는 PR CI가 돈다. CI가 없는 레포는 PR을 열기 직전에 로컬에서 전체를 한 번 돈다
- 버린 방법: 로컬도 전체(지금). 한 줄 문서 수정에도 4~5분이 들고 리뷰 회차마다 되풀이된다

### S2 · S5 표

- 표에 없는 파일이 바뀌면 전체를 돈다. 놓치는 쪽으로 실패하지 않게 하려는 것이다. 문서도 표에 넣는다. 이 레포는 스킬 문서 글자를 훅 테스트가 grep으로 검사하므로 「md는 건너뜀」(`hooks/validate-session-end.sh`의 기록 파일 규칙)을 그대로 쓸 수 없다
- 실패 확인(red) 판정에서는 그 step이 더하거나 고친 테스트 파일이 부분 실행에 들어가야 한다. 러너는 red도 `$step.test`를 `{since}`=step 시작 커밋으로 채워 돌리므로(`sdd_runner.py:765-770`), 표는 테스트 파일 자신을 그 묶음에 잇는다
- S5 레포 소유: 하네스가 깔린 레포에 지키라고 하는 것은 규칙 둘이다(표에 없는 파일이면 전체 · 새 묶음을 더할 때 표에 한 줄). 표의 자리와 꼴은 레포가 정한다. 템플릿 harness.json `verify` 주석이 이 규칙을 알린다
- 버린 방법(S5): 하네스 공용 키(예: `verifyMap`) + 템플릿으로 까는 고르는 스크립트. 새 키 · 깔리는 스크립트 · 업그레이드 경로가 계약이 되고, `vitest --changed` · `jest --changedSince`처럼 도구가 이미 바뀐 파일로 고르는 레포에는 쓸모없는 짐이다
- 이 레포의 꼴: `hooks/test-map.tsv`(한 줄 = 경로 glob · 묶음)를 `hooks/lib/test_pick.py`가 읽고, `bash hooks/test.sh --since <커밋>`이 고른 묶음만 돈다. 묶음은 본문(`hooks/test.sh`의 번호 케이스) · 러너 단위 · `hooks/tests/` 파일 하나하나다. 꼴의 정본은 표 파일 머리 주석이다
  - 본문의 문서 정합 케이스는 `hooks/tests/doc-consistency.sh`로 옮겼다. 본문에서 문서를 글자로 검사하는 곳이 그 케이스 하나라, 옮기면 문서만 바뀐 부분 실행이 본문(로컬 약 93초)을 돌지 않는다
  - 본문에 있던 `check_deny`(deny 패턴 검사 함수)는 앞으로 올렸다. `hooks/tests/rm-recursive-force.sh`가 본문 없이 돌 때도 쓰기 때문이다

### S4 기존 `$step.test`

- 러너 밖 쓰임: 리뷰 · 트랙 작업은 `{since}`에 브랜치 시작점(`git merge-base HEAD origin/<base>`, `<base>`는 `scripts/base-branch.sh` 출력)을 채운다. 키 이름이 `$step`인 까닭은 러너가 먼저 썼기 때문이고, 쓰임은 문서(템플릿 주석 · 리뷰 · 트랙 지시문)로 알린다
- `$step.test`가 없는 레포는 어디서나 `test`(전체)를 돈다. 깔린 레포는 바꾸지 않아도 지금처럼 돈다
- 러너 코드는 고치지 않는다(줄 A 소유)
- 버린 방법: 새 키(예: `verify.$changed`). 깔린 레포 계약 · init · 업그레이드 · doctor가 키 둘을 알아야 하고, 러너가 새 키를 모르니 줄 A 수정이 필요하다

### 한계

- 러너는 phase 마지막 step · 재개 step에서 여전히 전체를 돈다(`sdd_runner.py:404-419`). 빼는 실행 옵션 `--defer-full-test`가 이미 있고, 기본으로 켤지는 러너 호출 쪽(줄 A) 일이라 이 결정에 넣지 않았다
- 검사 상한(`hooks/lib/verify_busy.py`)은 `$` 키를 검사 명령 목록에 넣지 않는다. 이 레포는 부분 명령이 전체 명령(`bash hooks/test.sh`) 뒤에 인자를 붙인 꼴이라 상한이 같은 명령으로 센다. 부분 명령이 전체 명령과 다른 꼴인 레포에서는 부분 실행이 상한에 잡히지 않는다
- 표는 사람이 쓴다. 테스트가 어떤 파일을 읽는지 표가 놓치면 부분 실행은 그 테스트를 건너뛴다. 이것은 PR CI 전체 실행이 잡는다(S1)
