# 학습 레벨 — 분야마다 beginner · intermediate · advanced

> 이해 확인(PR 이해 게이트 · 빈틈 3곳 · 설명 리허설 · explain-diff 퀴즈)의 **형식 정본**이다. 각 스킬은 여기를 가리키고 형식을 다시 쓰지 않는다.
> 왜: 객관식 5문항이 처음 보는 분야(BE·인프라)에서는 이해보다 찍기가 많고 오래 걸렸다(2026-10-14 사용자 보고, 소요 시간 미측정). 처음 보는 분야는 키워드부터 설명하고, 확인 문항 없이 설명만 둔다(2026-10-15 사용자 결정, 이유 미기록).
> 왜(2): 초급·중급이 "이 diff가 무엇을 바꿨나"만 다뤄서 용어 한 줄 정의에서 끝났다 — 트랜잭션을 봐도 언제 쓰고 무엇을 조심하는지는 남지 않았다. 초급·중급은 **쓰인 기술의 큰 흐름**을 다루고, diff와는 "여기선 왜"로 잇는다(2026-10-17 사용자 결정 — 항목·개수·빈칸·반복·중급 구성 모두 인터뷰로 정함).

## 1. 레벨 파일 — `~/.claude/learning-level.json`

한 사람의 값이라 레포가 아니라 홈에 한 장 둔다. 모든 레포가 같은 값을 읽는다.

```json
{
  "levels": { "fe": "intermediate", "be": "beginner", "infra": "beginner", "domain": "beginner" },
  "history": [
    { "date": "2026-10-20", "area": "be", "level": "beginner", "source": "pr-quiz", "pass": true }
  ]
}
```

- **파일이 없거나 읽을 수 없거나 값이 빠졌으면 그 분야는 `beginner`이다.** 다른 사람이 이 플러그인을 쓰면 처음엔 전부 beginner 형식으로 나온다. 바꾸려면 위 파일을 만든다
- 레벨은 사람이 정한다. 스킬은 `levels`를 고치지 않는다 — 승급·강등은 제안만 하고 승인 뒤 사람이(또는 사람이 시킨 대로) 고친다
- `history`는 이해 확인을 끝낼 때마다 블록 하나에 한 줄 덧붙인다. beginner 블록은 확인 문항이 없어 적지 않는다(승급 시험 `weekly-test`만 남는다)(`source`: `pr-quiz` · `gap` · `rehearsal` · `explain-diff` · `weekly-test`). 강등 판정의 재료다. 덧붙이기 전 파일이 없으면 `levels`를 비운 채 만든다(빈 `levels` = 전부 beginner)

## 2. 분야 판정 — 바뀐 파일 경로로

| 분야 | 경로 신호 (하나라도 맞으면) |
|---|---|
| `fe` | `*.tsx` `*.jsx` `*.vue` `*.css` `*.scss` · `components/` `pages/` `app/`(웹 앱) · `apps/web*` |
| `be` | `*.kt` `*.java` `*.py`(서버) `*.go` · `src/main/` · `api/` `server/` `controller/` `service/` `repository/` · 마이그레이션 · `*.sql` |
| `infra` | `Dockerfile*` `docker-compose*` · `.github/workflows/` · `k8s/` `helm/` `charts/` `terraform/` `*.tf` · `nginx*` · 배포 `values*.yaml` |
| `domain` | 경로가 아니다. **PR마다 한 블록** — 이 변경이 사업·사용자에게 왜 필요한가 |

- 레포의 `CLAUDE.md`·`harness.json`이 앱 경로를 적어 두었으면 그걸 먼저 쓴다
- 둘 이상에 걸치면 바뀐 줄이 많은 쪽으로. 문서·설정만 바뀐 분야는 블록을 내지 않는다

## 3. 블록 형식

분야마다 블록 하나. 한 PR에 FE·BE가 섞이면 `[FE·intermediate]` `[BE·beginner]` `[도메인·beginner]`처럼 블록이 여러 개다.

| 레벨 | 블록 | 통과 |
|---|---|---|
| **beginner** | **기술 카드 2~3장 + 끝에 빈칸 1개.** 이 diff가 기대는 기술(문법·이름 바꾸기 말고 개념 — 트랜잭션·캐시·훅·리렌더·Docker 레이어 같은 것)을 2~3개 고른다. 하나뿐이면 1장. 카드 형식은 아래 「beginner 기술 카드」 | 없음 — 빈칸은 확인이 아니라 되새김이다. 정답을 바로 아래 보여 주고, 채점·`history`·draft가 없다 |
| **intermediate** | 객관식 3문항 — **큰 흐름 2**(이 diff에 쓰인 기술이 보통 언제 쓰이고 무엇이 함정인가) + **적용 1**(이 프로젝트에선 왜 이 기술을 이 자리에 썼나). 분야가 하나뿐이면 큰 흐름 3 + 적용 2. 중간 난이도·함정 문항 X | 절반 **초과** |
| **advanced** | 서술형 "왜 이렇게?" 1~2문항. 대안을 하나 들고 왜 안 골랐는지 묻는다 | 핵심 이유가 들어 있다(판정 근거 한 줄을 같이 낸다) |

### beginner 기술 카드

한 장에 여섯 항목, 항목마다 한 줄이 기본. 카드 한 장 8줄 이하, 블록 전체 25줄 이하 — 넘으면 카드 수를 줄인다(깊이를 깎지 않는다).

```
[BE·beginner] 트랜잭션
키워드      여러 저장을 "전부 되거나 전부 안 되거나" 한 묶음으로 — 12살이 알아듣는 말로
원래 맥락    보통 어떤 상황에서 쓰나 — 돈·재고처럼 둘 중 하나만 저장되면 안 되는 곳
여기선 왜    파일:줄 — 이 프로젝트의 어느 부분 때문에 썼나
안 쓰면      없으면 생기는 일 — 주문은 생겼는데 재고는 그대로인 사고
조심할 것    흔한 함정 1~2개 — 외부 API 호출을 묶음 안에 넣으면 오래 잠긴다
흐름 그림    가장 작은 그림 하나(콜트리·화살표) — 요청 → 묶음 시작 → 저장 2개 → 커밋 | 예외면 롤백
---
빈칸: 트랜잭션 안에서 예외가 나면 앞의 저장은 (   )된다.
정답: 롤백
```

- **비유**는 React/TS 쪽 하나까지(키워드나 원래 맥락 줄에)
- **이미 본 기술**: 이 레포 `_learn/inbox.md`에 같은 제목의 `종류: 기술` 카드가 있으면 「여기선 왜 · 조심할 것」 두 줄만 낸다. 원래 맥락은 이미 읽었다
- **남기기**: 처음 낸 카드는 `_learn/inbox.md`에 `종류: 기술` 카드로 한 장(제목 = 기술 이름). 같은 제목이 있으면 상태만 올린다 — 이 카드가 「이미 본 기술」 판정의 근거다
- **빈칸은 블록에 하나**: 카드들 중 가장 중요한 줄(대개 「안 쓰면」이나 「조심할 것」)에서 낸다
- 도메인 한 줄은 기술 카드에 넣지 않는다 — 도메인 블록이 따로 있다. 도메인 블록이 따로 없는 곳(빈틈 3곳)만 카드 뒤에 한 줄

도메인 블록은 레벨이 beginner이면 설명 두세 줄(문항 없음), intermediate이면 객관식 1, advanced이면 "이 정책이 바뀌면 무엇이 깨지나" 서술 1.

공통:
- 문항이 있는 블록(intermediate·advanced)은 정답을 먼저 보여 주지 않는다. 답은 한 줄로 받는다(`1b 2a | 서술: …`). beginner 블록만 있으면 답을 받지 않는다
- 채점 뒤 해설은 **전 문항** — 맞힌 것 ✅ 왜 맞나 한 줄 · 틀린 것 ❌ 정답 + 왜 틀렸나 두 줄. 찍어서 맞힌 것도 이해로 남긴다
- beginner 도메인 블록의 설명은 문항이 없어도 `_learn/inbox.md`에 `종류: 도메인 · 층: 회사 | 산업` 카드로 한 장 남긴다(도메인 지식을 쌓는 통로)
- 틀린 블록은 `_learn/inbox.md`에 `종류: 막힌 질문` 카드. 도메인 블록이면 `종류: 도메인 · 층: 회사 | 산업`(층 = 회사를 옮겨도 쓸모 있나 — 아니면 회사, 예면 산업)

## 4. 레벨 변경 — 제안만

- 승급 시험·판정은 사람이 정한 곳(예: 주간 회고)에서 돈다. beginner → intermediate 승급은 이 시험(intermediate 객관식)만이 근거다. 기준: 다음 단계 형식 시험을 **2주 연속 통과** → 승급 제안 · 평소 블록이 **2주 연속 미달** → 강등 제안
- 스킬은 제안 한 줄까지. `levels`를 고치는 건 사람 승인 뒤다
