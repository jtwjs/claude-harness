# 학습 레벨 — 분야마다 beginner · intermediate · advanced

> 이해 확인(PR 이해 게이트 · 빈틈 3곳 · 설명 리허설 · explain-diff 퀴즈)의 **형식 정본**이다. 각 스킬은 여기를 가리키고 형식을 다시 쓰지 않는다.
> 왜: 객관식 5문항이 처음 보는 분야(BE·인프라)에서는 이해보다 찍기가 많고 오래 걸렸다(2026-10-14 사용자 보고, 소요 시간 미측정). 처음 보는 분야는 키워드부터 설명하고 빈칸으로 확인한다.

## 1. 레벨 파일 — `~/.claude/learning-level.json`

한 사람의 값이라 레포가 아니라 홈에 한 장 둔다. 모든 레포가 같은 값을 읽는다.

```json
{
  "levels": { "fe": "intermediate", "be": "beginner", "infra": "beginner", "domain": "beginner" },
  "history": [
    { "date": "2026-10-20", "area": "be", "level": "beginner", "source": "pr-quiz", "pass": true }
  ]
}
```

- **파일이 없거나 읽을 수 없거나 값이 빠졌으면 그 분야는 `beginner`이다.** 다른 사람이 이 플러그인을 쓰면 처음엔 전부 beginner 형식으로 나온다. 바꾸려면 위 파일을 만든다
- 레벨은 사람이 정한다. 스킬은 `levels`를 고치지 않는다 — 승급·강등은 제안만 하고 승인 뒤 사람이(또는 사람이 시킨 대로) 고친다
- `history`는 이해 확인을 끝낼 때마다 블록 하나에 한 줄 덧붙인다(`source`: `pr-quiz` · `gap` · `rehearsal` · `explain-diff` · `weekly-test`). 강등 판정의 재료다. 덧붙이기 전 파일이 없으면 `levels`를 비운 채 만든다(빈 `levels` = 전부 beginner)

## 2. 분야 판정 — 바뀐 파일 경로로

| 분야 | 경로 신호 (하나라도 맞으면) |
|---|---|
| `fe` | `*.tsx` `*.jsx` `*.vue` `*.css` `*.scss` · `components/` `pages/` `app/`(웹 앱) · `apps/web*` |
| `be` | `*.kt` `*.java` `*.py`(서버) `*.go` · `src/main/` · `api/` `server/` `controller/` `service/` `repository/` · 마이그레이션 · `*.sql` |
| `infra` | `Dockerfile*` `docker-compose*` · `.github/workflows/` · `k8s/` `helm/` `charts/` `terraform/` `*.tf` · `nginx*` · 배포 `values*.yaml` |
| `domain` | 경로가 아니다. **PR마다 한 블록** — 이 변경이 사업·사용자에게 왜 필요한가 |

- 레포의 `CLAUDE.md`·`harness.json`이 앱 경로를 적어 두었으면 그걸 먼저 쓴다
- 둘 이상에 걸치면 바뀐 줄이 많은 쪽으로. 문서·설정만 바뀐 분야는 블록을 내지 않는다

## 3. 블록 형식

분야마다 블록 하나. 한 PR에 FE·BE가 섞이면 `[FE·intermediate]` `[BE·beginner]` `[도메인·beginner]`처럼 블록이 여러 개다.

| 레벨 | 블록 | 통과 |
|---|---|---|
| **beginner** | ① 키워드 2~3개 — 처음 보는 말을 한 줄씩 정의(React/TS 비유 하나 허용) ② 이 변경을 설명하는 문장 3~5줄, 핵심 낱말을 빈칸 `(___)` 3~5개로 ③ 도메인 한 줄 — 이게 사업·사용자에게 왜 필요한가 | 빈칸 절반 이상 |
| **intermediate** | 객관식 2~3문항(분야가 하나뿐이면 5). 중간 난이도·함정 X — 왜 이렇게 바꿨나, 바꾸면 무엇이 달라지나 | 절반 **초과** |
| **advanced** | 서술형 "왜 이렇게?" 1~2문항. 대안을 하나 들고 왜 안 골랐는지 묻는다 | 핵심 이유가 들어 있다(판정 근거 한 줄을 같이 낸다) |

도메인 블록은 레벨이 beginner이면 빈칸 1~2개짜리 두세 줄, intermediate이면 객관식 1, advanced이면 "이 정책이 바뀌면 무엇이 깨지나" 서술 1.

공통:
- 정답을 먼저 보여 주지 않는다. 답은 한 줄로 받는다(`1b 2a | 빈칸: 트랜잭션, 롤백, …`)
- 채점 뒤 해설은 **전 문항** — 맞힌 것 ✅ 왜 맞나 한 줄 · 틀린 것 ❌ 정답 + 왜 틀렸나 두 줄. 찍어서 맞힌 것도 이해로 남긴다
- beginner 빈칸은 뜻이 맞으면 낱말이 달라도 맞다(동의어·영문 표기)
- 틀린 블록은 `_learn/inbox.md`에 `종류: 막힌 질문` 카드. 도메인 블록이면 `종류: 도메인 · 층: 회사 | 산업`(층 = 회사를 옮겨도 쓸모 있나 — 아니면 회사, 예면 산업)

## 4. 레벨 변경 — 제안만

- 승급 시험·판정은 사람이 정한 곳(예: 주간 회고)에서 돈다. 기준: 다음 단계 형식 시험을 **2주 연속 통과** → 승급 제안 · 평소 블록이 **2주 연속 미달** → 강등 제안
- 스킬은 제안 한 줄까지. `levels`를 고치는 건 사람 승인 뒤다
