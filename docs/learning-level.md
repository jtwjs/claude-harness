# 학습 카드 형식

> 작업 끝 학습 카드의 「개념/키워드」 칸 **형식 정본**이다. 카드는 작업 보고에 싣고 레포에 쓰지 않는다. 카드의 나머지 항목은 `skills/sdd/SKILL.md` ⑤ 마무리 「학습 카드」가 정한다. 각 스킬은 여기를 가리키고 형식을 다시 쓰지 않는다.

## 기술 카드

이 diff가 기대는 기술(문법·이름 바꾸기 말고 개념 — 트랜잭션·캐시·훅·리렌더·Docker 레이어 같은 것)을 2~3개 고른다. 하나뿐이면 1장.

한 장에 여섯 항목, 항목마다 한 줄이 기본. 카드 한 장 8줄 이하, 카드 전체 25줄 이하 — 넘으면 카드 수를 줄인다(깊이를 깎지 않는다).

```
[BE] 트랜잭션
키워드      여러 저장을 "전부 되거나 전부 안 되거나" 한 묶음으로 — 12살이 알아듣는 말로
원래 맥락    보통 어떤 상황에서 쓰나 — 돈·재고처럼 둘 중 하나만 저장되면 안 되는 곳
여기선 왜    파일:줄 — 이 프로젝트의 어느 부분 때문에 썼나
안 쓰면      없으면 생기는 일 — 주문은 생겼는데 재고는 그대로인 사고
조심할 것    흔한 함정 1~2개 — 외부 API 호출을 묶음 안에 넣으면 오래 잠긴다
흐름 그림    가장 작은 그림 하나(콜트리·화살표) — 요청 → 묶음 시작 → 저장 2개 → 커밋 | 예외면 롤백
---
빈칸: 트랜잭션 안에서 예외가 나면 앞의 저장은 (   )된다.
정답: 롤백
```

- **비유**는 쓰지 않는다. 키워드·원래 맥락 줄도 실제 사례(이 레포의 코드·상황)로 쓰고, 비유는 사람이 원할 때만 하나
- **빈칸은 카드 전체에 하나**: 카드들 중 가장 중요한 줄(대개 「안 쓰면」이나 「조심할 것」)에서 낸다. 확인이 아니라 되새김이라 정답을 바로 아래 보여 주고 채점하지 않는다
