# 에이전트가 읽는 글 (write-for-agents)

스킬 본문 · description · 규칙 · CLAUDE.md · step 파일 · 위임 지시문처럼 에이전트가 읽고 따르는 글을 쓰거나 고칠 때 따른다. 사람이 읽는 글은 `write-for-readers.md`.

번호는 다른 스킬이 인용한다. 지우거나 순서를 바꾸지 말고, 새 규칙은 마지막 번호 뒤에 붙인다.

1. **단계마다 끝났음을 판정할 기준을 둔다.** 「이해되면 다음으로」처럼 흐린 끝은 에이전트가 단계를 서둘러 닫게 만든다. 끝은 확인할 수 있는 상태로 쓴다(파일이 있다 · 명령이 통과한다 · 표의 행이 전부 채워졌다). 「모든 X를 확인했다」처럼 빠짐없음을 요구하는 기준이 일을 더 깊게 시킨다.
2. **금지보다 할 일을 쓴다.** 금지문은 막으려는 행동을 글 안에 불러와 오히려 떠올리게 한다. 바라는 행동을 쓴다(「주석은 한 줄로」). 긍정문으로 못 쓰는 울타리만 금지로 두고, 그때도 할 일을 같이 쓴다.
3. **환경이 정본인 것은 옮겨 적지 않는다.** 설정 파일 · 스크립트 목록 · 폴더 구조 · `--help` 출력은 한 번 열면 나온다. 옮겨 적은 사본은 환경이 바뀌면 낡는다. 적는 것은 찾아도 안 나오는 것뿐이다: 적히지 않은 관례 · 고른 이유 · 설정이 말해 주지 않는 함정.
4. **늘 실리는 글일수록 더 깎는다.** description · 자동으로 실리는 규칙은 부를 때가 아니어도 매번 자리를 차지한다. 거기서는 낱말 하나도 값을 한다. 부를 조건을 앞에 두고, 같은 조건을 다른 말로 두 번 쓰지 않는다. 자동 입구 description 글자 수는 `scripts/always-on.py`가 잰다.
5. **겹치는 지시는 지운다.** 같은 뜻을 두 곳에 쓰거나 모델이 이미 하는 일을 시키는 문장은 `subtract-before-you-add.md`(「지시문도 같다」)대로 지운다. 여기서 다시 적지 않는다.
6. **스킬마다 범위 · 보고 형식 · 재시도 상한 · 애매할 때 기본값을 적는다.** 넷 중 하나가 비면 에이전트가 그 칸을 추측으로 채운다: 범위 밖까지 고치거나, 보고 꼴이 매번 달라지거나, 실패를 끝없이 다시 돌리거나, 애매한 자리에서 멈춘다.
7. **강조어 대신 평서문으로 쓴다.** 대문자 경고 · 굵은 글씨 남발 · 「반드시」 같은 말을 빼고 뜻은 그대로 둔다. 강조가 많으면 어느 것이 정말 중요한지 가려지지 않고, 강조한 줄만 지나치게 따르게 된다.

## 맡길 때 세 칸

에이전트에 일을 맡기는 글(즉석 Agent 호출 · 지휘 지시문 · 리뷰어 넘김)에는 아래 세 칸을 채운다. 받는 쪽은 맡긴 쪽 대화를 보지 못해서, 빈 칸은 추측으로 채워진다.

- **의도** — 무엇을 왜 하는지, 채우는 수용 조건(번호가 있으면 번호). 의도가 없으면 받는 쪽은 끝났는지도, 바꾼 것이 목적을 깨는지도 가리지 못한다.
- **effort** — 받는 쪽 역할의 값을 넘긴다. 값은 일의 느낌이 아니라 역할이 정한다(하네스 ADR-019 C2). 넘기지 않으면 역할과 상관없는 기본값으로 돈다.
- **검증** — 끝을 무엇으로 확인하는지(돌릴 명령 · 채워질 표 · 볼 상태). 1번의 끝 기준을 맡기는 글에도 둔다.

검증자에게 fork를 쓰지 않는다는 규칙은 이 문서가 아니라 호출 자리(`sdd-run` §2 · `sdd-review` 「위임」)에 있다 — 호출 직전에 보여야 해서다.
