# 전제를 친다 (attack-the-premise)

같은 전제를 깐 수정이 두 번 이상 같은 검사(테스트 · 빌드 · 리뷰 · 측정)에서 실패했을 때 따른다.

- **수정이 아니라 전제를 의심한다.** 같은 전제 위에서 고친 세 번째 수정도 같은 자리에서 막힌다.
- **전제를 한 문장으로 적는다.** 실패한 수정이 모두 깔고 있던 가정 하나다.
- **다음 수정 전에 전제를 시험한다.** 전제가 거짓이면 결과가 달라질 관찰 하나를 골라 실제로 해 본다. 실패가 얼마나 큰지만 보지 말고 어디에 몰리는지(분포)를 본다. 크기는 얼마나 나쁜지만 말하고, 분포는 어디서 생기는지를 가리킨다.
- **증거가 전제와 어긋나면** 실패들이 공통으로 가진 것 중 전제가 예측하지 못한 것을 찾는다. 한 부분이 늘 지는 쪽에 놓이면, 뒤에서 치우는 장치를 더하지 말고 그것을 거기 놓는 원인을 바꾼다.
  - 원인을 바꾸는 일이 설계 결정(회의에서 "왜 이렇게?"를 받을 결정)이면 바꾸기 전에 `ask-questions` 원칙대로 사람에게 묻는다.
- 전제를 적고 시험하기 전에는 다음 수정을 시작하지 않는다.
