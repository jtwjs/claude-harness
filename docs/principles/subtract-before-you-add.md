# 빼고 나서 더한다 (subtract-before-you-add)

기능 추가 · 리팩터 · 다시 쓰기의 작업 순서를 정할 때 따른다.

- **기본값은 빼기다. 빼기가 먼저, 짓기가 나중이다.** 고칠 범위 안의 죽은 코드 · 겹치는 검증 · 내용 없는 참조를 먼저 걷고, 단순해진 바닥 위에 짓는다. 복잡한 바닥에 더하면 새 코드가 옛 복잡함을 떠받치게 된다.
- **다듬기 전에 자른다.** 최소한까지 줄인 뒤에 품질에 공을 들인다. 지울 코드를 다듬은 시간은 버려진다.
- **본 사용에 맞춰 설계한다.** 일어난 적 없는 예외 상황(추측한 엣지 케이스)을 위해 짓지 않는다.
- **스펙이 요구하지 않는 검증기 · 파서 · 가드를 넣지 않는다.** 필요해 보이면 넣지 말고 스펙 빈칸으로 묻는다. 보안 · 데이터 무결성처럼 빠지면 사고가 나는 것일수록 묻는다.
- **지시문(프롬프트 · 스킬 본문)도 같다.** 겹치는 지시와 과한 템플릿을 지운다.
- **새 내용이 없는 참조는 지운다.** 「여기를 보라」만 남은 껍데기를 두지 않는다.
- **떠날 때는 같거나 더 작은 겉면으로.** 건드린 범위는 들어올 때보다 조금 단순하고, 바깥에 드러난 API · 옵션 · 지시는 같거나 적어야 한다.
  - 범위 밖에서 본 뺄 거리는 지우지 말고 후보로 한 줄 보고한다. 범위 밖을 지우면 리뷰할 diff가 커지고, 남이 쓰던 것을 모르고 지울 수 있다.
