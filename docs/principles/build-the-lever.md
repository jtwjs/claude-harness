# 손 대신 도구 · 글 대신 구조 (build-the-lever · encode-lessons-in-structure)

두 원칙을 한 파일에 둔다. 손으로 할 일 앞에서는 앞 절, 같은 지시 · 교정이 되풀이될 때는 뒤 절을 따른다.

## 손 대신 도구를 만든다 (build-the-lever)

사소하지 않은 일(수정 · 옮기기 · 분석 · 검사)을 손으로 하려 할 때 따른다. 대량 작업만이 아니다.

- **문턱은 횟수가 아니라 사소함이다.** 사소하지 않으면 손 대신 그 일을 하거나 증명하는 도구(codemod · 스크립트 · 생성기 · 다시 돌릴 수 있는 검사)를 만든다. 뻔한 수정 몇 개뿐이면 손으로 한다.
- **만들 도구의 결과물이 분명할 때 만든다.** 도구가 무엇을 내면 맞는지 말할 수 있어야 한다. 모호하면 만들지 않고 반복 관찰을 기다린다. 같은 일이 다시 나오면 뒤 절의 횟수로 센다.
- **첫 단위는 손으로 하고**, 도구를 만든 뒤 그 단위에 다시 돌려 같은 결과가 나오는지로 증명한다. 여러 번 돌려도 안전하게 만든다.
- **결정적 도구(같은 입력에 같은 결과)가 여러 에이전트에 나눠 맡기기보다 낫다.** 나눠 맡길 때는 방법 · 검증 계약 · 울타리(건드리면 안 되는 것)를 위임받는 쪽이 읽기만 하고 고칠 수 없는 지시문 한 장에 쓴다.
- **일을 해내거나 증명하는 가장 작은 스크립트를 만든다.** 프레임워크를 만들지 않는다.
- 만들었으면 diff에 파일(스크립트 · codemod · 생성기 · 위임 지시문)이 남는다. 도구는 리뷰어가 다시 돌려 볼 수 있는 산출물이다. 세션을 넘겨 쓸 일이면 커밋한다.

## 교훈은 글 대신 구조로 (encode-lessons-in-structure)

같은 지시를 두 번째 쓰거나 같은 교정이 되풀이될 때 따른다.

- **두 번째는 「후보」로 표시만 한다.** 구조는 아직 만들지 않는다. 두 번까지는 우연일 수 있다.
- **3회부터 구조로 옮길 승격 후보다.** 횟수는 `harness-gaps`가 센다.
- **옮길 때는 지시를 더 쓰지 않고 구조로 바꾼다.** 린트 · 메타데이터 플래그(frontmatter 등) · 실행 중 검사 · 스크립트.
- 판단이 필요해 구조로 옮길 수 없으면 지시를 더 눈에 띄는 자리에 두고 실패 예시를 하나 붙인다.
- **구조로 고쳤으면 구조만 남긴다.** 같은 내용의 지시 문장은 지운다. 지시는 증상이다.
