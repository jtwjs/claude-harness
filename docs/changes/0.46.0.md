# 0.46.0

- 설계서 틀: sdd 설계서 틀(`skills/sdd/references/design.md` 「설계서 틀」)이 옛 8칸에서 간단히(한 줄 요약 · 문제 · 전체 구조 · 고른 안과 버린 안 · 트레이드오프 5칸 + 우리 칸) · 자세히(목표와 비목표 · 대안 비교 · 상황별 동작 · 열린 질문과 누가 정하나 4칸) · 아주 자세히(상세 설계 · 공통 관심사 · 배포와 롤백 3칸)로 바뀌었다. 우리 칸에 제약 · 가정 · 비기능 수치 · 사람이 볼 것 줄이 있다. 옛 「비기능」 칸은 우리 칸 「비기능 수치」 줄과 「공통 관심사」로 옮겨 왔다. 초안에는 아주 자세히 3칸 제목만 두고(칸 순서 검사 대상), ARCHITECTURE · ADR 뒤 지휘(혼자 도는 sdd면 그 세션)가 다시 써서 채운다(설계서 순서 1 · 7)(#106 · #87)
- 세 장 출처 칸: PRD는 설계서 칸에서 뽑는다. PRD · ARCHITECTURE · ADR 세 장 모두 줄마다 끝에 출처 칸 `(← 칸 이름)`을 단다. `👤`가 있는 줄은 `👤` 앞에 단다. 설계서에 없는 줄은 `(← 검증 세션)`이다. 표에서는 행 끝이 아니라 따로 둔 「출처」 열에 단다(행 끝에 달면 마지막 열에 들어간다). ADR 「결정할 것」 표에는 달지 않는다(마지막 열이 주체라 꼬리표가 들어가면 러너 관문이 그 결정을 닫힌 것으로 센다). 제목 · 표 머리 · mermaid · 코드 블록에도 달지 않는다. Readiness 9 · 10이 새 칸 이름 · 출처 칸 · 주제 이름으로 대조한다. ADR 「설계서 결정 번호」 칸은 「설계 문서 주제」(설계서 「고른 안과 버린 안」 행의 주제 이름, 링크 없음)로 바뀌었다. ARCHITECTURE 틀에 불변 규칙 · 코드 지도 · 요청 하나 따라가기 · 배포와 롤백이 더해졌다(#106 · #87)
- 칸 순서 검사: 새 스크립트 `skills/sdd/scripts/design_doc_check.py`(python3 표준 라이브러리만). 설계서를 화면에 열기 전에 돌리고, 실패면 열지 않고 먼저 고친다. 정본 칸 목록은 `design.md` 「설계서 틀」 블록에서 읽는다. 통과 exit 0 · 빠짐/순서 어긋남 exit 1 · 파일 못 읽음/틀 블록 못 찾음 exit 2. 칸 제목만 보고 내용은 보지 않는다(#106 · #87)
- 업그레이드 영향
  - 다음 sdd 설계서부터 새 틀(간단히 · 자세히 · 아주 자세히)로 쓴다. 초안에도 아주 자세히 3칸 제목은 있어야 칸 순서 검사를 통과한다. 칸 이름이 바뀌어, 옛 칸(「결정할 것 / 결정한 것」 · 「기능 요구사항」 · 「사용자 흐름 · 수용 기준」 · 「비기능」 · 「제약 · 가정」)을 찾는 습관은 새 칸(「고른 안과 버린 안」 · 「열린 질문과 누가 정하나」 · 「목표와 비목표」 · 「상황별 동작」 · 우리 칸 · 「공통 관심사」)으로 옮긴다. 결정 묶음 답은 설계서 「고른 안과 버린 안」에 덧붙인다(#106)
  - 새로 쓰는 PRD · ARCHITECTURE · ADR은 줄마다 출처 칸을 단다. 표는 행 끝이 아니라 「출처」 열에 달고, ADR 「결정할 것」 표에는 달지 않는다. ADR 「설계서 결정 번호」 칸 대신 「설계 문서 주제」 칸을 쓴다. 러너가 읽는 꼴(ADR 「결정할 것」 표 · PRD 「→ 결정:」)은 그대로다(#106)
  - 설계서를 화면에 열기 전에 칸 순서 검사를 돌린다. python3만 있으면 되고 설치할 것은 없다. #87 전에 옛 틀로 이미 시작한 설계서는 검사하지 않고 옛 틀 그대로 둔다(#106)
