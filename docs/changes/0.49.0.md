- 머지 확인 훅: 위험 명령 훅이 단순한 PR 머지 명령 하나(`gh pr merge <번호> [아는 옵션]`)를 보면 그 PR을 읽는다. 세 조건(규칙 파일 0 · Risk 30 이하 · CI 전부 통과)을 모두 채우고, `--match-head-commit <소문자 16진수 7~40자>`가 PR 머리 커밋의 앞부분과 맞고, `--auto`가 없을 때만 확인 창을 띄우지 않는다. 하나라도 아니거나 PR을 못 읽으면 지금처럼 확인 창이다. 통과해도 뒤 검사(운영 DB 등)는 끝까지 돈다. 2026-10-13 「dry-run 동안 늘 사람 확인」을 대체한다(ADR-026 D5)(#140 · #141)
- 재귀 강제 삭제 차단: 위험 명령 훅의 새 deny 항목 `rm-recursive-force`가 한 삭제 명령에 재귀와 강제가 같이 있으면 경로와 상관없이 바로 거부한다(확인을 묻지 않음). 거부 메시지가 대신할 길을 적는다. 옛 루트 · 홈 항목은 그대로다(#130)
- push 훅 건너뛰기 차단: `git push --no-verify`를 훅 패턴과 템플릿 `settings.json` deny 3줄로 막는다. `-n`은 push에서 dry-run이라 막지 않는다. 새 사고를 「장치로 막기 · 임시 한 줄 + 장치 이슈 · 한 줄」 갈래로 판정하는 규칙이 템플릿 `non-obvious-patterns.md` 「규칙」 절에 생겼고 REFLECT가 그 절을 가리킨다(#126)
- 템플릿 확인받기: 템플릿 `settings.json`에 배포 · 공개 명령 확인받기(`permissions.ask`) 9줄을 두었다(PR 머지 · `gh release create` · npm/pnpm/yarn publish · 태그 push 계열). `harness-init`이 레포 고유 배포 · 마이그레이션 명령을 돌리지 않고 실재만 확인해 후보로 보이고, 승인한 줄만 ask에 더한다. `harness-doctor` §7-d가 ask 줄 명령의 실재를 본다(#128)
- 테스트 범위(ADR-025): 전체 테스트는 PR CI에서 한 번 돌고, 로컬(작업 중 · 리뷰 회차 · 러너 step 판정)은 바꾼 부분의 테스트만 돈다. CI가 없는 레포는 PR 직전 로컬 전체 1번. 새 키 없이 기존 `verify.$step.test` + `{since}`를 쓰고, 리뷰 · 트랙 작업은 `{since}`를 브랜치 시작점으로 채운다. 템플릿 `harness.json` 설명 · PR 템플릿 검증 줄 · `sdd-review` · 트랙 템플릿을 맞췄다(#134)
- 업그레이드 모드 공통 rules: `harness-init` 업그레이드 모드가 템플릿 공통 rules(`testing.md` · `non-obvious-patterns.md` 등)도 스택 팩 규칙과 같은 3방향 diff로 갱신한다. 기준 판 찾기가 다음 버전 커밋을 집던 버그를 고쳤고, 기준 판 출처를 설치 캐시 → 마켓플레이스 git → 2방향 순서로 바꿨다(#131)
- harness-doctor 문서 품질: §9 문서 품질 세 축(설계 명확성 · 최신성 · 실행 가능성)을 더했다(읽기 전용, 등급 없음). §2 정방향 경로 점검에 `.claude/references/`를 넣고, §5에 `CLAUDE.md` · rules 줄 수를 더했다(#136)

- 업그레이드 영향
  - 설치본만 올리면 따라오는 것: 위험 명령 훅(머지 확인 · 재귀 강제 삭제 · push 훅 건너뛰기), 판정 기록 훅, 러너(#135 · #137), 문서 크기 환기 훅(`cadence-reminder.sh`, #138), 스킬 문서(`conductor` · `pr-write` · `how` · `harness-doctor` · `harness-init` · `sdd` · `sdd-review` · `sdd-run`). 새 훅은 설치 뒤 새로 연 세션부터 먹는다(#140 · #130 · #126)
  - 업그레이드 모드(`harness-init`)가 보여 주고 승인받아 합치는 것: 템플릿 `settings.json`의 deny 3줄(#126) · ask 9줄(#128), 공통 rules인 템플릿 `non-obvious-patterns.md` 「규칙」 절(#126). 이번 판부터 업그레이드 모드가 공통 rules를 3방향 diff로 보여 준다(#131). 0.48.0에서 손으로 옮기라던 `testing.md`도 이제 업그레이드 모드로 받는다. `renames.tsv`의 옛 이름 두 개도 고쳐 쓴다(#138)
  - 손으로 옮길 것(업그레이드 모드 표에 행이 없음): 템플릿 `harness.json` `verify` 설명(업그레이드 모드는 version만 올림, #134), PR 템플릿 검증 줄(#134), 트랙 템플릿(#134 · #140), 템플릿 `CLAUDE.md` 훅 끄기 금지 줄(#126), 템플릿 README 한 줄(#132 · #138)
  - 동작이 바뀌어 막히는 것: 명령 줄에 직접 쓴 재귀 강제 삭제(임시 폴더 정리 한 줄 포함)는 경로와 상관없이 거부된다(확인 창 없음). 스크립트 파일 안의 것은 훅이 보지 않는다(#130). `git push --no-verify`는 거부된다(#126). 러너 `start`는 `index.json`에 커밋 안 된 `test_edits` 칸이 있으면 멈춘다(#135)
  - 동작이 바뀌어 지나가는 것: 세 조건 · 머리 커밋 대조를 채운 PR 머지는 훅 확인 창 없이 지나간다. 훅은 확인 창을 안 띄울 뿐 허가를 내지 않으므로, 레포 `settings.json`에 템플릿 ask 줄(`Bash(gh pr merge*)`, #128)을 옮겼으면 Claude Code 확인받기는 그대로 뜬다. `--match-head-commit` 없는 머지 · `--auto` 머지는 조건을 채워도 확인 창이다(#140 · #141)
  - 사람이 치지 않은 턴에는 판정 지시를 내지 않아서, 모델이 판정 기록 원장(`ledger`)에 그 턴의 줄을 쓰지 않는다. 그 전 줄은 그대로 남는다(#140)
  - `verify.$step`이 없는 깐 레포는 어디서나 전체 test를 돈다. 바꾼 부분만 돌리려면 `$step.test`에 `{since}`를 받는 명령을 둔다(#134)
