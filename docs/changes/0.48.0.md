# 0.48.0

- 테스트 양 문구: 템플릿 `templates/.claude/rules/testing.md`의 양 제한 줄(「일단 다 테스트 금지」 · 「기능당 통합 대개 1개」)이 「쓸모 있는 테스트는 아끼지 않는다. 커버리지는 목표가 아니라 빈 곳을 찾는 신호다」로 바뀌었다. 겹치던 원칙 ①(「목을 테스트하지 않는다」)을 지워 「원칙 둘」이 됐다. 엣지 5축 질문 표가 `agents/test-writer.md`에서 `testing.md` §2로 옮겨 와 한 곳에만 있다. `test-writer`는 `testing.md` §0 · §2를 가리키고, `testing.md`가 없거나 §2에 질문 표가 없으면(옛 판 사본) 다섯 축 이름만으로 훑고 그랬다고 보고에 적는다(#114 · #73)
- FE 엣지 사용자 장면: 스택 팩 `templates/stacks/react-vite/rules/testing-fe.md`의 통합 칸이 「흐름마다 통합(개수는 미리 정하지 않는다)」으로 바뀌었고, 엣지 5축을 사용자 장면(버튼 연타 · 뒤로가기 · 끊긴 네트워크 · 붙여넣기 등)으로 옮긴 절 「엣지 5축을 사용자 장면으로」가 생겼다(#114 · #73)
- 러너 판정 4: 테스트 먼저 step(`tdd: true`)에서 red 뒤 구현이 테스트 파일 이름을 바꾸거나(테스트 밖으로 옮김 포함) 공백 · 한글 경로 테스트를 고치면, 판정 4가 옛 경로를 red 내용으로 복원하고 새 경로를 지운 뒤 실패로 보낸다. 전에는 `git diff --name-only` 기본값으로 목록을 받아 이 꼴들이 빠졌다(#115 · #102)
- 헤드리스 step 대화 기록 차단: 헤드리스 `run`이 `claude -p`에 `--disallowedTools`로 `.claude/projects`가 든 셸 명령과 `~/.claude/projects`의 Read · Grep · Glob을 막는다(러너 상수 `HEADLESS_DENY`). 헤드리스 호출 환경에는 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`을 늘 넣어 auto memory를 끈다. 세션 안 모드(`prompt` · `judge`)는 그대로다. step 금지 문구는 「`~/.claude` 아래(대화 기록 · 원장 · 설정)를 읽지 않는다. 레포 안 `.claude/`와 플러그인 스킬 문서는 예외」가 됐고, `sdd-plan`은 step이 실제 데이터 꼴이 필요하면 가린 샘플을 step 파일에 넣거나 blocked로 요청하게 한다(#117 · #75 · #118)
- 비밀 파일 출력 훅: 위험 명령 훅의 `secret-file-read` 패턴이 읽기 낱말을 명령 자리(줄 처음, 구분자 뒤, 큰따옴표 안 명령 치환 뒤)에서만 본다. 따옴표 본문 · `--head` 옵션 속 글자로 막던 오탐이 닫혔다. 따옴표로 감싼 경로 읽기는 계속 막는다(#119 · #103)
- 업그레이드 영향
  - 공통 규칙 `testing.md`는 업그레이드(`harness-init` 업그레이드 모드) 때 들어가지 않는다. 업그레이드 모드 표에 공통 rules 행이 없어, 이미 깐 레포의 `.claude/rules/testing.md`는 덮어쓰지도 안내하지도 않는다(#74가 이 빈 곳을 다룬다). 새 문구 · §2 질문 표를 쓰려면 `templates/.claude/rules/testing.md`를 레포 사본에 직접 옮긴다. 옮기지 않으면 `test-writer`(플러그인)만 새 판이 되어 §2 질문 표를 못 찾고 축 이름만으로 훑는다고 보고하며, 레포 사본에는 옛 양 제한 줄이 남는다. 「테스트하지 않는다」 목록은 그대로라 `harness.json`의 `tdd.exclude`와는 어긋나지 않는다(#114)
  - 스택 팩 규칙 `testing-fe.md`는 덮어쓰지 않는다. 업그레이드 모드가 3방향 diff(레포 `harness.version` 판 템플릿 · 지금 템플릿 · 레포 사본)를 보여 주고 파일마다 「템플릿으로 · 레포 판 유지 · 줄 단위로 합치기」를 고르게 한다. 공통 `testing.md`를 옮기지 않고 `testing-fe.md`만 템플릿으로 고르면 한 레포 안에서 양 문구가 서로 어긋난다(#114)
  - 헤드리스 step의 `claude -p`에 거부 규칙 넷과 auto memory 끄는 환경 변수가 붙는다. 플러그인 러너라 설치본만 올리면 따라온다. 셸 규칙이 글자 매칭이라, 헤드리스 step이 레포 안 `.claude/projects` 글자가 든 검사 명령(레포 상대 경로 · 문서 grep)을 돌려도 막힌다. 반대로 경로를 나눠 쓰거나 변수로 숨기는 우회는 못 막는다(금지 문구가 받는다)(#117)
  - 비밀 파일 출력 훅 패턴이 바뀐다. 플러그인 훅이라 설치본만 올리면 모든 레포에 따라온다. 옛 패턴이 막던 꼴 일부(앞 낱말 목록 밖 낱말이 붙은 읽기 · 여러 줄 따옴표 본문 뒤 같은 줄의 읽기)가 지나간다. 남는 한계는 `hooks/deny-patterns.yaml`의 `secret-file-read` 주석이 정본이다(#119)
  - 러너 판정 4는 판정 동작만 바뀌어 업그레이드 할 일이 없다. red 뒤 테스트 이름을 바꾸던 구현 시도는 이제 실패한다(#115)
- 문서: `docs/sdd-runner.md` — 헤드리스 차단 항목 · 한계 두 줄 · auto memory 끄기(#117), `test_edits` 항목 「다음 시도(새 BASE)부터」 → 「남은 재시도에는 안 먹고, 멈춘 뒤 재개(새 BASE)부터」(#115)
