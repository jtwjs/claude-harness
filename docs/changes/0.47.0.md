# 0.47.0

- 트랙 지시문 틀: `templates/.claude/references/track-brief.md` 표에 「멈출 조건」(이 작업에만 걸리는 멈춤. 걸리면 다시 시도하지 않고 출력과 함께 지휘에 보고한다. 러너가 재시도하는 실패는 러너 상한이 먼저다. 공통 멈춤만 있으면 「공통 규칙만」) · 「사람이 볼 것(후보)」(검증 세션이 PRD 수용 조건의 `👤`로 확정한다. 없으면 「없음」) 칸이 생겼다. 「끝나면 지휘에 보고」 판정 재료에 6번(실제로 돌린 검증 명령과 출력 끝부분 — 지휘는 다시 돌리지 않고 이 출력으로 판정한다) · 7번(머지 질문 재료 — 형식은 `conductor` SKILL 「사용자에게 올리는 현황」이 정본)이 생겨 판정 재료가 5줄에서 7줄이 됐다(#109 · #108)
- 한 문장 diff 디스패치: `conductor` 디스패치(§5, `skills/conductor/references/dispatch.md`)에 한 줄이 생겼다. diff를 한 문장으로 설명할 수 있는 작업은 새 worktree 세션 하나로 끝내고(나눔 모드로 나누지 않음, 「세션 역할」은 「하나」), 머지를 묻기 전에 `sdd` 「③ REVIEW」의 세션 하나 모드대로 리뷰한다(#109)
- PRD `👤` 기준 출처: `sdd` 설계 참고 문서(`skills/sdd/references/design.md` 「PRD.md」)에서 수용 조건 `👤 <기준 한 구절>`을 고르는 곳에 설계서 「사람이 볼 것」 칸과 트랙 지시문 「사람이 볼 것(후보)」 칸이 더해졌다(전에는 지시문 「개인 기록 관련 사실」 칸만)(#109)
- 업그레이드 영향
  - 트랙 지시문 틀의 새 칸 4개(「멈출 조건」 · 「사람이 볼 것(후보)」 · 판정 재료 6 · 7번)는 업그레이드(`harness-init` 업그레이드 모드) 때 들어가지 않는다. 업그레이드 모드 표에 `.claude/references/track-brief.md` 행이 없어, 이미 깐 레포의 사본은 덮어쓰지도 안내하지도 않는다. 지휘는 레포 사본을 채워 넘기므로, 새 칸을 쓰려면 `templates/.claude/references/track-brief.md`의 해당 줄을 레포 사본에 직접 옮긴다. 새로 까는 레포(병렬 트랙 ⑧ 예)는 새 틀로 깔린다(#109)
  - 0.45.0 변경 이력의 「트랙 지시문 칸 이름은 다음 업그레이드 때 따라온다」는 위와 같은 이유로 틀렸다. 그 칸 이름(「개인 기록 관련 사실(선택)」)도 손으로 옮겨야 한다
  - 지휘는 한 문장 diff 작업을 세션 하나로 디스패치한다. 플러그인 스킬이라 설치본만 올리면 따라온다(#109)
  - PRD를 쓸 때 `👤` 기준을 설계서 「사람이 볼 것」 칸과 지시문 「사람이 볼 것(후보)」 칸에서도 고른다. 러너가 읽는 꼴은 그대로다(#109)
