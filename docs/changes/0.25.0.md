# 0.25.0

- step 명령(0.25.0, 2026-10-19): 앱별 verify 의 `$step`(예 `{"test": "vitest run --changed {since}"}`)을 판정 3·6 · 서브에이전트 지시문 · 헤드리스 Stop 훅이 step 중간에 쓰고, phase 마지막(측정 step 포함) · 재개 · 앱 밖 파일 step 은 전체 명령. 유통 대시보드에서 앱 하나의 test 전체가 step 마다 judge · RED · 서브에이전트 · Stop 훅에서 여러 번 돌아 server 52분 · web 타임아웃 재실행이 났고, 테스트 수에 비례하는 비용이라 사용자가 「step 은 영향받은 것만, 마지막에 전체」로 결정. 설계 리뷰(서브에이전트)에서 「같은 패키지」 고르기는 기준 사고(PollJobTest, 다른 패키지를 import)를 못 잡는다는 지적 → 고르기는 레포 명령에 맡기고(import 역추적 권장) 러너는 `{since}`만 넘긴다. `{files}` 치환자는 명령이 `git diff {since}`로 같은 걸 얻어서 뺐다. 마지막 step 의 전체 verify 가 깨지면 그 앱의 step 명령을 한 번 더 돌려, 통과하면(또는 측정 step 이면) 앞 step 탓으로 보고 재시도 대신 blocked 로 사람에게 넘긴다 — 그 step 에이전트가 고칠 수 없는 실패를 전체 test × 4회로 붙잡던 문제(사용자 요청으로 같은 버전에 포함). 원인 step 자동 이분 탐색은 하지 않는다(전체 test 를 여러 번 돌려 비용이 다시 커진다)
