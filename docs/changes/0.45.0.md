# 0.45.0

- 러너 테스트 보호(ADR-024): 테스트를 먼저 쓰지 않는 step(`tdd: false`, 측정 step 포함)에서 구현이 BASE에 있던 테스트 파일을 고치거나 지우면, 러너가 BASE 내용으로 되돌림 커밋을 만들고 실패로 보고해 재시도한다(판정 4'). 새 테스트 파일(BASE에 없던 경로)은 남긴다. 이름 바꾸기 · 테스트 밖으로 옮김은 옛 경로 복원으로 본다(`--no-renames`, 공백 · 비ASCII 경로 그대로). blocked 보고 · error 멈춤 때도 기록 전에 같은 되돌림을 돌리고 이유 끝에 되돌린 경로를 붙인다(#104 · #91)
- `test_edits` 칸: `tdd: false` step의 선택 칸 `{"<경로>": "<이유 한 줄>"}`. 적힌 경로는 판정 4'에서 빠진다. 경로는 글자 그대로(glob 없음), 이름 바꾸기는 옛 경로를 적는다. 칸은 진행 중 index.json이 아니라 BASE 커밋의 계획에서 읽어, 구현이 써 넣은 칸은 허가가 아니다. `start`가 부작용 전에 꼴을 본다(객체 아님 · `tdd: true` step · 이유 빈칸 · glob 글자 · `./` 시작 · 테스트 파일 아님 · `phases/` 아래면 종료 1)(#104)
- 나눔 모드: `prompt --role impl`이 BASE가 없으면 HEAD로 고정한다. 전에는 `tdd: false` step의 `judge`가 「BASE 필요」로 거절했다(#104)
- 템플릿 CI 비밀값 검사: 템플릿 CI에 PR 커밋 범위(`base..head`)만 보는 `secret-scan` 잡(gitleaks 8.30.1, 버전 · sha256 고정)을 단일 · 앱별 두 형태에 넣었다. `pull_request`에서만 돌고, 범위가 깨지면(빈 값 · 없는 커밋 · 얕은 clone) 통과 대신 실패한다. 앱별 형태는 `ci-gate`의 `needs`에 더했다. 템플릿 `.gitignore`에 `.env` 줄을 넣었다. 실제 GitHub Actions에서는 아직 안 돌려 봤다(#101 · #71)
- 트랙 지시문 템플릿: 「도메인 지식 링크(선택)」 칸이 「개인 기록 관련 사실(선택)」이 됐다. 지휘가 읽고 고른 사실만 적고 경로는 넣지 않는다(ADR-022 D7)(#97 · #93)
- 업그레이드 영향
  - 러너: 기존 계획의 `tdd: false` step(측정 포함)이 칸 없이 원래 있던 테스트 파일을 고치거나 지우면, 이제 되돌리고 실패 → 재시도한다. 일부러 고쳐야 하면 그 step의 `test_edits`에 `경로 → 이유`로 적고 계획을 커밋한다. step 도중 더한 칸은 남은 재시도에는 안 먹고, 멈춘 뒤 재개(새 BASE)부터 적용된다. 이동 리팩터의 이동 step(테스트 파일 이름이 바뀜)이 가장 먼저 걸리는 꼴이다(#104)
  - 템플릿 CI 비밀값 검사는 새로 까는 레포에만 들어간다. 이미 깔린 레포는 업그레이드(`harness-init`) 때 CI 파일을 고치지 않고, 레포 `ci.yml`에 `gitleaks`가 없으면 잡을 복사하라는 안내 한 줄만 받는다. `.env` 줄은 다른 빠진 `.gitignore` 줄처럼 diff 승인 뒤 들어간다(#101)
  - 트랙 지시문 칸 이름은 다음 업그레이드 때 따라온다(#97)
