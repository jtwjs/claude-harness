# 0.42.0

- 훅 기록이 전체 훅으로 넓어졌다 — 0.41.0의 3개에 이어 나머지 훅 8개도(이제 11개 전부) 끝나는 모든 경로에서 결과(`blocked` · `warn` · `ask` · 건너뜀 등) 한 줄을 남긴다. 이제 Bash 호출마다 기록이 쌓이고, 기록 파일 회전 · 상한은 아직 없다. 기록 폴더가 없을 때 리다이렉트 오류가 훅 stderr에 섞이던 것도 고쳤다(#56)
- 하네스 없는 폴더에서는 조용하다: 판정 지시 훅(`hypothesis-gate`)은 하네스 레포와 지휘 자리에서만 켜지고, 그 밖에서는 출력 · 원장 기록을 하지 않는다. `block-dangerous-bash`는 하네스 없는 폴더에서도 그대로 막는다(#56)
- 버전 알림: 레포의 `.claude/harness.json` `harness.version`이 설치본 버전과 다르면 세션 시작에 「하네스 A → B, /harness-init 업그레이드 모드」 한 줄을 띄운다. 같거나 설정이 없으면 0줄(#56)
- `scripts/always-on.py`가 모델이 늘 보는 설명(자동 입구 스킬 + 에이전트 description) 글자 수를 잰다. `harness-doctor` §5와 `release.sh`가 이 값을 같이 보여 준다(#56)
- 새 레포 deny 템플릿: `harness-init`이 `templates/.claude/settings.json`(permissions.deny 28줄 — 커밋 훅 건너뛰기 · 보호 브랜치 강제 push · 원격 기준 hard reset · 보호 브랜치 삭제 · 루트/홈 통째 삭제 · 비밀 파일 읽기)을 같이 깐다. 업그레이드 모드는 빠진 줄만 승인 뒤 합친다. deny는 allow로 풀 수 없어 막히면 그 줄을 지워야 한다(#57)
- 강조어 평문: skills · agents · templates의 강조어 11줄을 평문으로 바꿨다(뜻은 그대로). 180자를 넘던 description 2개를 줄여 모델이 늘 읽는 설명이 2,219 → 2,150자가 됐다(#57)
- 설계 도구 흡수(ADR-017): `sdd-plan`은 기본 PRD 하나 = phase 하나, phase는 세로 · step은 층으로 나눈다. `sdd` 설계(`design.md`)에 Readiness 8(phase 나눔) · 용어 겨루기 · 질문지 초안 · 버릴 시제품이 들고, 키워드 표는 PRD로 옮기며 ADR은 3조건이 셋 다 맞을 때만 쓴다. `code-reviewer` 축 3에 삭제 테스트 · 구현체 하나뿐인 이음매, 새 원칙 문서 `docs/principles/write-for-agents.md`, 질문은 한 번에 하나가 기본이고 서로 독립이면 3개까지 묶는다(#59)
- 검증 · 구현 두 세션(나눔 모드, ADR-019): 테스트를 쓰는 검증 세션과 구현 세션을 나눌 수 있다. `sdd`는 「세션 모드 — 나눔 / 하나」를 고르고, 나눔이면 검증 세션이 설계 · 리뷰 · 회고 · 마무리를, 구현 세션이 구현만 맡는다. `conductor`는 두 세션을 같은 worktree에서 역할별 `--effort`로 연다. 옵션 없이 쓰면 지금처럼 세션 하나(#78)
- 러너 RED 판정: `sdd_runner.py`에 `prompt --role test|impl` · `judge --red`(테스트 커밋이 RED인지 판정해 step을 `red`로) · 차례 검사(차례가 아니면 아무것도 바꾸지 않고 종료 3)가 들었다. 새 꼴 step(`## 의도` 있음)은 의도나 tdd step의 엣지 5축 칸(빈 값·경계 / 비정상 입력 / 실패 경로 / 상태 전이 / 동시성)이 비면 돌지 않고, 칸의 테스트 이름이 테스트 커밋에 없으면 RED 위반이다. 옛 꼴 step은 경고만(#78)
- 오류 꼬리: 러너 verify 실패 사유에 출력 끝 40줄을 붙인다. 전체 테스트를 끝으로 미루는 `--defer-full-test`도 더했다(#78)
- 의도 / effort 전달: 요청서 세 칸(의도 · effort · 검증)을 track-brief 템플릿 · `write-for-agents.md` 「맡길 때 세 칸」 · `code-reviewer` 넘김(`INTENT`)에 넣었다. 러너는 역할로 effort를 정해 `prompt`는 stderr에 `▶ effort <값>`을, 헤드리스는 `claude -p --effort`로 넘긴다. 원장에 `intent` · `effort` · `verify` 선택 칸이 생겼고, 세션 간 메시지 · 서브에이전트 보고만 있는 턴에는 판정 지시를 내지 않는다(#78)
- 도메인 검증 칸: `sdd-review`에 수용 조건 대조(AC별 테스트 위치 표) · 「사람이 볼 것」(PRD 👤 항목)이 들고, `code-reviewer`를 부르는 조건을 `harness.json` `review.gatePaths`(템플릿 선택 키) · Risk · 확인 필요로 정한다. 세 줄 요약 셋째 줄은 `위험: … · 사람이 볼 것 N개`, `pr-write` 본문에 「모델이 검증한 것」 · 「사람이 볼 것」 두 절, `conductor` 머지 질문 한 줄 꼴(`Risk n · 심각도 · 사람이 볼 것 n개 · 규칙 diff 있음/없음`)(#78)
- `sdd-plan` step 템플릿이 6절(`## 의도` 추가)이 되고 엣지 5축 칸 · `red` 필드가 생겼다(#78)
- eval 틀: 레포 루트 `evals/`(case 17개 · regex 채점기)와 `scripts/eval-variant.sh` · `scripts/eval-tally.py`를 더했다. 플러그인 동작(스킬 · 훅)은 바뀌지 않는다(#62)
