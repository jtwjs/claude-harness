# ADR — 가설 게이트 원장 (plugin 쪽)

> 번호는 이 폴더 안에서만 센다. 다른 기능의 ADR 번호와 무관하다.

## ADR-001 프롬프트 시점 훅(`UserPromptSubmit`)을 새로 단다

- 상태: 수락 (2026-11-13)
- 맥락: 맡기는 순간 개입하려면 프롬프트마다 도는 장치가 필요하다. 지금 `hooks/hooks.json`의 이벤트는 `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SessionStart`, `Stop`뿐이라 프롬프트 시점이 없다(확인함).
- 결정: `UserPromptSubmit` 훅 하나를 더한다. 모든 레포에서 돈다.
- 결정 주체: 사람(프롬프트 시점 훅, 모든 레포) 
- 대안: `Stop` 훅에서 사후에 쓰기(맡기는 순간 개입이 안 됨) / `SessionStart`(세션당 한 번이라 맡김 단위가 아님)
- 결과: 프롬프트마다 판정 지시가 모델 컨텍스트에 들어가 토큰이 는다(`미측정`). 이 훅이 모델 컨텍스트에 실제로 들어가는지는 추정이라 구현 첫 단계에서 확인한다.

## ADR-002 줄은 모델이 도우미를 불러 직접 붙인다

- 상태: 수락 (2026-11-13)
- 맥락: 판정(`hyp rec acc why rebut`)은 직전 응답과 이 프롬프트를 읽어야 해서 훅이 못 한다. 모델이 해야 한다.
- 결정: 훅은 지시만 주입하고, 모델이 응답 중 `ledger.py append`를 Bash로 불러 한 줄을 붙인다. 누락을 확인하는 `Stop` 훅은 두지 않는다.
- 결정 주체: 사람(이유 미기재)
- 대안: `Stop` 훅이 누락을 확인하고 되돌려 쓰게 하기(누락은 줄지만 응답마다 비용과 되돌림 반복 위험)
- 결과: 모델이 빼먹으면 줄이 조용히 사라지고, 연속 값이 끊기거나 늦게 켜진다. 누락률은 측정으로만 본다. 또한 프롬프트마다 Bash 호출이 생겨 허용 목록에 이 명령이 없으면 매번 권한 확인이 뜰 수 있다(`미측정: 실제 세션에서 확인 / 구현 첫 단계`). 허용 목록 추가가 필요하면 설치 안내에 적는다.

## ADR-003 원장은 JSONL 한 파일, 전역 위치

- 상태: 수락 (2026-11-13)
- 맥락: desk는 여러 레포의 줄을 한 곳에서 읽는다. 칸이 나중에 늘어도 읽는 쪽이 안 깨져야 한다.
- 결정: `~/.claude/hypothesis-ledger.jsonl` 하나. 줄마다 JSON 한 개, 추가 전용.
- 결정 주체: 사람
- 대안: 레포마다 파일(레포를 넘는 상태가 안 이어짐) / SQLite(가볍게 가는 원칙에 어긋남)
- 결과: 원장을 잘라내거나 회전하면 재요구 상태가 사라진다. 여러 레포의 훅이 한 파일에 동시에 붙일 때의 경합은 추가 한 줄이라 낮다고 추정한다(`미측정`).

## ADR-004 재요구 상태는 저장하지 않고 줄 순서로 계산한다

- 상태: 수락 (2026-11-13)
- 맥락: 상태 파일을 두면 원장과 어긋날 수 있다. 줄 순서만으로 계산 가능한지 desk가 물었고 가능하다고 답했다(조건: 원장을 자르지 않고 `rebut` 칸이 있을 것).
- 결정: 매 프롬프트마다 원장을 훑어 계산한다. 별도 상태 파일 없음.
- 결정 주체: AI 추천 수용
- 대안: 상태 파일을 따로 갱신(원장과 어긋날 위험, 쓰기 경로 증가)
- 결과: 원장이 길어지면 훅 시간이 는다(`미측정: 줄 수천 개로 훅 시간 재기 / 구현 첫 단계`). 기준 횟수를 바꾸면 과거 상태도 새 기준으로 다시 계산된다.

## ADR-005 구현은 bash 진입점 + 파이썬 도우미

- 상태: 수락 (2026-11-13)
- 맥락: 이 레포의 훅은 bash이고 복잡한 판별은 `hooks/lib/prod_db.py` 같은 파이썬에 둔다(확인함). 줄 순서 계산은 bash로 쓰면 macOS 기본 bash 3.2에서 깨지기 쉽다(0.35.0에서 겪음).
- 결정: 진입점 `hooks/hypothesis-gate.sh`는 얇게, 계산·쓰기는 `hooks/lib/ledger.py`.
- 결정 주체: AI 추천 수용 (문서 승인 때 주석 없이 수락)
- 대안: 전부 bash(3.2 호환 위험) / 별도 실행 파일(새 의존 추가)
- 결과: 파이썬 3이 있어야 한다. 이 레포의 다른 훅이 이미 같은 전제다.

## ADR-006 기준 횟수는 개인 설정 파일에서 읽는다

- 상태: 수락 (2026-11-13)
- 맥락: 기준 횟수는 첫 2~4주 기록을 본 뒤 사람이 정한다. 코드에 박지 않는다.
- 결정: `~/.claude/hypothesis-gate.json`의 `threshold`. 파일이나 값이 없으면 재요구는 켜지지 않고 줄만 쌓인다. 이 레포의 다른 개인 설정(`~/.claude/learning-level.json` 등)과 같은 자리다.
- 결정 주체: AI 추천 수용 (문서 승인 때 주석 없이 수락)
- 대안: 환경 변수(`CLAUDE_VERIFY_MAX`처럼, 셸을 새로 열 때마다 값이 보장되지 않음) / 이 플러그인 안 설정(업데이트 때 덮어써짐)
- 결과: 값을 바꾸는 방법이 파일 한 줄 편집이다. desk가 쓰는 `config.json`의 `hypothesis_ledger`(원장 위치)와는 별개다.

## ADR-007 적중 줄은 sdd REFLECT에서 한 번에 쓰고 사람이 정정한다

- 상태: 수락 (2026-11-13)
- 맥락: 적중(`hyp`가 맞았나)은 결과가 알려져야 판정할 수 있다. 맡김 시점에는 알 수 없다.
- 결정: sdd REFLECT 직전에 `ledger.py pending-hits`로 그 작업의 대상 줄을 모으고, 모델이 `right|partial|wrong`을 제안하고, 사람이 정정하면 `by=finn`, 그대로 두면 `by=model`로 `hit`를 쓴다.
- 결정 주체: 사람 (이유: sdd 단계에서 사람이 정정할 수 있어서)
- 대안: 매 프롬프트 판정 지시에 "결과가 드러나면 적중도 쓴다"를 더하기(별도 단계가 없어 가볍지만 시점이 모호해 모델이 놓치기 쉽고 지시가 길어짐)
- 결과: sdd 밖(`task=null`) 작업은 적중이 안 쌓인다. 사람이 대부분 그대로 두면 `by=model`만 남아 판정 정확도를 못 믿게 된다(`by` 비율은 desk에서 볼 수 있음). 이 설계는 sdd 스킬 본문을 고친다.

## ADR-008 게이트 보정은 sdd REFLECT에서 사람이 확정하고 보정 줄로 남긴다

- 상태: 수락 (2026-11-13)
- 맥락: 게이트(`schema|api|error|delete|security`)는 모델이 프롬프트 시점에 판정한다. 놓치면 그 줄은 `gate=null`이라 연속 값 계산에서 빠진다. 작업이 끝난 뒤 diff를 보면 놓친 걸 알 수 있다. 원장은 추가 전용이라 원 줄을 못 고친다.
- 결정: sdd REFLECT에서 그 작업의 `gate=null` 줄(`pending-gates`)과 diff를 모델이 대조해 후보를 보이고, 사람이 확정한 것만 `gate-fix`로 보정 줄 `{ref, gate, by:finn}`을 붙인다. 유효한 `gate`는 마지막 보정 줄의 값이다. 적중 줄(ADR-007)과 같은 방식이다.
- 결정 주체: 사람 (시점: sdd REFLECT, 기록 방식: 보정 줄. 둘 다 이유 미기재)
- 대안: 응답마다 `Stop` 훅이 diff를 훑기(sdd 밖도 되지만 응답마다 비용, 규칙이 틀리면 잡음) / 보정을 따로 파일에 두기(원장 한 파일은 안 깨지지만 파일이 둘이 되어 상태 계산과 desk가 둘을 읽어야 함)
- 결과: desk가 보정 줄을 합쳐 읽어야 한다. 같은 원 줄의 `gate`가 나중에 바뀌므로 연속 값이 과거로 거슬러 다시 계산된다(기준 횟수 변경과 같은 성질). sdd 밖(`task=null`) 작업은 보정되지 않는다. 원장에 프롬프트 원문이 없어서 REFLECT 때 모델이 줄과 프롬프트를 맞춰야 하고, 세션이 압축되면 못 맞출 수 있다(`미측정`). 이 설계는 sdd 스킬 본문을 고친다.

## ADR-009 줄에 난이도 칸 `diff`를 더하고 `ts`에 난수 꼬리를 붙인다

- 상태: 수락 (2026-11-13)
- 맥락: 쉬운 가설만 쓰는 쏠림을 보려면 가설의 어려움이 줄에 남아야 한다(desk가 요청). 또 `ts`가 `ref` 식별자인데 밀리초라 같은 순간의 두 줄이 겹칠 수 있다(sdd 리뷰 2회차).
- 결정: 맡김 줄에 `diff`(`easy|mid|hard|null`)를 모델이 같은 판정 호출에서 적는다. 참고용이라 상태 계산에 쓰지 않고 사람 정정 단계도 두지 않는다. `ts`는 `<ISO 마이크로초>#<hex 4자리>`로 바꾸고 `ref`는 그 문자열 통째로 맞춘다.
- 결정 주체: 사람(칸을 두기, 범위·되돌리기 어려움 기준, 참고용) / AI 추천 수용(선례 없음 기준, 합치는 규칙, 값 집합과 칸 이름, `ts` 방식 A)
- 대안: `diff`에 REFLECT 사람 정정 단계 지금 넣기(계산에 쓸 때 쏠림을 바로잡지만 단계가 늘어 가볍게 가는 원칙과 부딪침. 데이터를 본 뒤 보정 줄 `{ref, diff, by}`로 추가 가능) / `ts` 겹침을 별도 `id` 칸으로 해결(`ts`가 깨끗한 시각이지만 `ref`가 바뀌어 desk 파서와 이미 쌓인 줄 해석이 같이 바뀜)
- 결과: 모델이 `easy`로 쏠리면 이 칸은 믿기 어렵다(분포와 `hit` 대조로 첫 2~4주 뒤 확인, `미측정`). `ts`가 순수 시각이 아니라 desk는 `#` 앞까지 시각으로 읽는다. 겹침 확률은 0이 아니다(동시 50번 쓰기 1회 시행에서 겹침 0, 더 큰 N은 `미측정`). 판정 문구가 길어져 프롬프트마다 주입 길이가 는다(`미측정: 훅 stdout wc -m`).
