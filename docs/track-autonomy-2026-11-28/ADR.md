- 맥락: 트랙은 지시문 밖 결정을 모두 결정 묶음으로 지휘에 올리고(`skills/conductor/references/seat.md:36` · `decisions.md:14`), 머지는 지휘가 사용자 승인을 받아 한다(`skills/conductor/SKILL.md:45`). ### D1 설계 밖 결정은 트랙이 정한다

- 지휘를 거치는 것: 설계 결정(스키마 · API 계약 · 에러 처리 · 삭제 · 보안), 한도 밖 유료 실행, 되돌릴 수 없는 일, 규칙 diff(`CLAUDE.md` · `.claude/rules/**`)
- 그 밖(범위 · 경로 · 구현 선택 · 임계 해석 등)은 트랙이 정한다. 그 이슈에 댓글 4줄로 남긴다: 결정 · 대안 · 고른 이유 · 감수한 대가. 결정 주체는 「트랙, ADR-026」. 지휘에는 한 줄만 보낸다
- 애매하면 지휘를 거친다
- 버린 방법: 지금처럼 모든 결정을 결정 묶음으로 올림. 범위 · 경로 선택에도 지휘 → 사용자 왕복이 생기고, 사용자 Inbox에 사용자가 정하지 않아도 되는 질문이 쌓인다

### D2 조건을 채운 PR은 트랙이 머지한다

- 조건 다섯을 모두 채우면 트랙이 머지한다: Risk 0~30 · 남은 리뷰 지적 🟢 또는 없음 · 새 맥락 `code-reviewer` 1회 실행 · 규칙 diff 없음 · PR CI 통과
- 명령: `gh pr merge <N> -R <owner>/<repo> --squash --match-head-commit <head>`. `--match-head-commit`은 확인한 커밋 뒤에 새 커밋이 올라왔으면 머지를 거절한다
- 머지 뒤 PR이 끝낸 이슈를 확인한다. `Closes`로 닫혔는지 보고, `Closes` 없이 끝낸 이슈는 PR · 머지 커밋을 적고 닫는다. 일부만 끝났으면 남은 것을 댓글로 남긴다. 지휘에는 머지 해시 한 줄만 보낸다
- 조건을 하나라도 못 채우면 지금처럼 머지 질문 재료를 지휘에 보낸다(`skills/conductor/SKILL.md` 「사용자에게 올리는 현황」의 머지 질문 줄)
- 버린 방법: 지휘가 머지(지금). 조건을 채운 PR도 지휘 대기와 사용자 승인 한 줄을 거친다

### D3 작은 유료 실측은 미리 승인한다

- 범위: haiku 모델, 이슈당 3회까지, 원격이 없는 임시 레포에서만
- 쓴 횟수와 비용(`total_cost_usd`)을 PR에 적는다. 넘으면 지휘에 묻는다
- 함정(#68에서 확인): Claude Code는 세션 스크래치 폴더(`claude/<project>/<session>/scratchpad` 꼴) 안의 `CLAUDE.md` · rules를 띄우지 않는다. 규칙 로드를 재는 실측은 그 폴더 밖 임시 레포가 필요하다. 스크래치 밖에 만드는 것은 세션 규칙상 따로 허락을 받는다

### D4 판정 기록 훅은 사용자 프롬프트에만

- 판정 지시를 내지 않는 턴: Orca 알림(「You have N orchestration message」) · 백그라운드 완료(`<task-notification>` 블록) · 플러그인 메시지(Inbox 답 포함, 「The … plugin sent a message」) · 다른 세션 메시지(`<cross-session-message>`, ADR-019 D3) · 압축 뒤 이어 가기 요약
- 프롬프트 전체가 그 꼴일 때만 거른다. 사람 글이 붙으면 사람 입력으로 본다. 판별이 안 되면 사람 입력으로 본다(판정 지시를 그대로 낸다)
- 끝 조건: 다섯 종류 프롬프트에 훅 출력 0, 사용자 프롬프트에는 지금과 같은 출력(`hooks/tests/ledger-intent.sh`)
- 한계: 백그라운드 완료 · 플러그인 메시지 · 압축 요약의 원문 꼴은 세션 화면에 보이는 꼴로 정했다. 훅이 받는 원문과 같은지는 실사용 원장으로 확인한다. 다르면 사람 입력으로 떨어져 지금처럼 줄이 붙는다(놓치는 쪽이 아니라 남는 쪽)

### D5 머지 확인 훅은 조건을 직접 확인한다

- `gh pr merge`가 나오면 훅이 그 PR을 한 번 읽는다(`gh pr view <N> -R <repo> --json body,files,changedFiles,statusCheckRollup`). 세 조건을 모두 채우면 확인 창 없이 통과한다
  1. 규칙 파일(`CLAUDE.md` · `.claude/rules/**`) 변경 0
  2. PR 본문 Risk Score 30 이하
  3. CI 체크 전부 통과(체크가 없으면 통과가 아니다)
- 하나라도 못 채우면 지금처럼 확인 창(ask)이다. PR을 못 읽음 · Risk 값을 못 찾음 · 바뀐 파일 목록을 다 못 받음 · 시간 초과(기본 10초) · 머지 명령이 둘 이상도 확인 창이다(모르면 묻는 쪽)
- 「어떤 PR · 어떤 커밋이 머지되는지」가 명령만으로 확실할 때만 세 조건을 본다(트랙이 정함, ADR-026 D1). 단순한 `gh pr merge <번호> [아는 옵션]` 하나이고, `--match-head-commit <7자 이상>`이 PR 머리 커밋과 맞고, `--auto`가 없어야 한다. 아니면 확인 창이다
- 조건은 이 셋뿐이다. 사용자가 고른 범위라 넓히거나 줄이지 않는다. D2의 나머지 둘(남은 리뷰 지적 · `code-reviewer` 실행)은 기계가 읽을 정본이 없어 트랙이 머지 전에 확인한다
- 판정은 `hooks/lib/pr_merge_ok.py`, 훅 자리는 `hooks/block-dangerous-bash.sh`. 2026-10-13 「자동 머지 판정 dry-run 동안 늘 사람 확인」 결정을 대체한다
- 버린 방법: 늘 확인 창(지금 — D2와 부딪친다) · 훅에서 머지 확인을 뺌(조건을 못 채운 머지도 확인 없이 나간다)
