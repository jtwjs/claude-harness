# ADR — task-observer 전역 후보 적재 (observer 트랙)

> 번호는 지휘(`conductor`)가 발급한다. 결정 원문은 jtwjs/claude-harness 이슈 #35.

## ADR-015 task-observer 전역 후보를 개인 원장에 `후보`로 적재 — 주 1회 헤드리스

- 상태: 수락 (2026-11-23)
- 맥락: task-observer 기록이 0건이다(`~/orca` · 개인 볼트 어디에도 `observations.md` 없음, 2026-11-23). 레포 안 REFLECT는 그 레포 기록만 보여서 「여러 레포에 걸친 반복」을 셀 수 없다. 결정 이슈 #35.
- 결정:
  - REFLECT는 `observations.md` 범위 칸(`레포 고유 | 전역 후보`)을 내용으로 판정만 하고, 원장에는 레포 2곳 이상일 때만 주 1회 헤드리스가 묶어 쓴다.
  - 하네스가 원장에 직접 행을 쓰되 상태는 늘 `후보`(`열림`은 사람이 볼트 `/friction review`에서). 월별 파일에 근거, ID는 원장을 읽어 다음 번호.
  - 헤드리스 = 일요일 17:30 `claude -p`(도구 없음 · 세션 저장 없음). 재지시 · 재교정 · 불발 · 반복 절차는 모델 판정, 미위임은 `phases/*/index.json`(blocked · retries≥3)을 스크립트로만 세서 0이 아니면 사유를 모델 입력에 붙인다.
  - 재지시/재교정 경계: 이미 한 결과를 고치면 재교정, 하기 전에 미리 말하면 재지시.
  - 원장 경로는 개인 설정 `~/.claude/task-observer.json`의 `ledger`에서만. 없으면 원장을 쓰지 않는다. 훑을 레포는 설정 없이 7일 대화 기록의 `cwd`에서.
  - 모든 쓰기는 `skills/task-observer/scripts/observer.py append` 한 곳. 모델은 후보 JSON만 낸다.
- 결정 주체: 범위 판정 · 원장 쓰기 · 실행 방식 · 5종 배분은 사람(나누는 위치 · 시각 · 배분은 AI 추천 수용). 경계 · 설정 파일 · 레포 목록은 AI(사람 반려 없음). #35 「정한 것」 표.
- 대안: 후보 파일까지만 쓰고 사람이 볼트에서 `/friction`으로 옮김(원장 형식 결합은 없지만 적재 한 단계를 사람이 더 함) / 스크립트만으로 헤드리스(비용 0, 재지시 · 재교정은 못 잡음) / 원장에 바로 `열림`(잘못 묶은 행이 3회를 가짜로 채움)
- 대가: 원장 행 형식(11칸 · `F-NNN` · 상태 이름 · 월별 파일 항목)이 공개 플러그인 코드에 들어간다. 원장 형식이 바뀌면 `observer.py`도 같이 고친다. 원장에서 표를 못 찾으면 쓰지 않고 exit 2로 알린다.
- 결과: plist · install 등록 · weekly 알림 한 줄은 레포 밖이라 따로 한다. 설정이 없는 공개 사용자는 지금과 같다(REFLECT 범위 칸만 늘어남). 헤드리스는 구독 사용량을 쓴다(`ANTHROPIC_API_KEY`가 있으면 API 과금 — 경고 한 줄).
