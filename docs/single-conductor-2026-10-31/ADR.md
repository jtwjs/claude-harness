# ADR — 지휘 세션 하나 · 검사 동시 실행 상한

## ADR-001 지휘 설정은 `~/.claude/conductor.json`

- 상태: 제안
- 맥락: 스크립트·훅·상태줄이 "지휘 자리"와 "대상 레포"를 알아야 한다. 경로는 머신마다 다르다. vault CLAUDE.md의 목록은 모델만 읽고 스크립트가 못 읽는다.
- 결정: `~/.claude/conductor.json` — `{"seat": "~/wiki", "repos": ["~/orca/bv-admin", "~/fastview/viewus-distribution-dashboard"]}`. `~`는 펼쳐 읽는다. 파일이 없거나 깨지면 지휘 기능이 꺼진 것으로 본다(지금 동작).
- 결정 주체: AI 추천 수용
- 대안: vault CLAUDE.md 목록(스크립트가 못 읽음) / 환경변수(배열이 불편, 상태줄 프로세스에 안 닿을 수 있음) / 레포마다 표식 파일(레포 사본을 더 고쳐야 함)
- 결과: 새 머신에서는 사람이 한 번 만든다. `gh-accounts.txt`와 같은 자리·같은 성격이다.

## ADR-002 지휘 자리 판정은 cwd 기준

- 상태: 제안
- 맥락: 훅·상태줄이 "지금 지휘 세션인가"를 알아야 한다. 세션 이름은 사람이 `/rename`으로 바꾸는 값이고, 훅·상태줄 입력에 늘 들어온다는 근거를 확인하지 못했다.
- 결정: cwd의 git toplevel(git이 아니면 cwd)이 `seat`와 같으면 지휘 자리다.
- 결정 주체: AI 추천 수용
- 대안: 세션 이름 `conductor`로 판정 — 입력에 이름이 오는지 [확인 필요]. 오더라도 vault의 다른 세션과 지휘를 가를 수는 있지만, 이름을 안 바꾼 첫 순간에 훅이 안 돈다
- 결과: vault에서 연 세션은 전부 지휘 자리로 본다 → 지휘가 아닌 vault 세션에도 SessionStart 현황이 들어간다. 줄 수는 레포당 2~3줄로 묶는다. 거슬리면 그때 이름 판정을 더한다.

## ADR-003 vault 자리에서 `-R` 없는 gh 쓰기는 막는다

- 상태: 제안
- 맥락: `block-dangerous-bash.sh`는 `-R`이 없으면 cwd origin으로 owner를 정한다(:102-103). vault에서는 vault 레포가 owner가 되어, 지휘가 `-R`을 빠뜨리면 vault 레포에 이슈·댓글이 생긴다. 계정 검사도 틀린 owner로 돈다.
- 결정: cwd가 지휘 자리(ADR-002)이고 gh 쓰기(issue·pr·release × create·comment·edit·close·reopen·review·delete·merge)에 `-R`/`--repo`가 없으면 exit 2 + `-R <owner>/<repo>` 안내. 지휘 자리가 아니면 지금 동작. `gh api graphql` 쓰기는 이번 범위 밖(지금도 검사 대상 아님) — 스킬 문구로 `-R`·owner 명시
- 결정 주체: 사람(훅으로 강제) / AI 추천 수용(지휘 자리에서만)
- 대안: 모든 하네스 없는 폴더에서 막기 — 개인 레포 작업까지 막힌다 / 스킬 문구만 — 한 번 빠뜨리면 사고
- 결과: vault 세션에서 사람이 vault 레포 자체에 이슈를 열 때도 `-R jtwjs/personal_wiki`를 붙여야 한다.

## ADR-004 운영 DB 판정의 대상 레포는 명령 머리에서 읽는다

- 상태: 제안
- 맥락: 운영 DB 절은 cwd 레포의 `harness.json`만 본다(:121-122). vault에는 없어 `git -C`·`cd`로 다른 레포를 건드리는 명령이 가드를 지나간다.
- 결정: 명령이 `cd <경로> &&|;` 또는 `git -C <경로>`로 시작하면 그 경로의 git toplevel을 대상 레포로 쓴다. 아니면 cwd(지금과 같음). 경로가 없거나 git이 아니면 cwd로 되돌린다.
- 결정 주체: AI 추천 수용
- 대안: 지휘 설정의 대상 레포 전부의 가드를 OR로 적용 — 오탐이 늘고 레포마다 판정 근거가 섞인다
- 결과: 명령 중간의 `cd`(예: `foo && cd x && psql`)는 잡지 않는다. 지휘는 코드를 고치지 않아 DB 명령을 칠 일이 드물다 — 실제로 지나간 사례가 나오면 넓힌다.

## ADR-005 압축 뒤 맥락은 SessionStart 훅이 넣는다

- 상태: 제안
- 맥락: 지휘 하나가 레포 여럿을 맡으면 압축 요약이 레포마다 열린 일을 빠뜨린다. SessionStart는 시작·재개·압축 뒤에 돈다. 환기는 SessionStart의 additionalContext만 살아남았다(Stop 훅 실측 0).
- 결정: 새 훅 `conductor-context.sh`(SessionStart). 지휘 자리면 대상 레포마다 `tracks_status.py --compact` 한 줄 + `gh issue list -R <repo> --label conductor --state open` 번호·제목(레포당 최대 10)을 additionalContext로. gh는 레포당 5초 제한, 실패하면 `(조회 실패)` 한 줄.
- 결정 주체: 사람(넣기로) / AI 추천 수용(SessionStart·형식)
- 대안: PostCompact 훅 — 압축 직후만 돌고 재개·새 세션은 못 덮는다
- 결과: 지휘 자리 세션 시작이 레포 수 × 최대 5초 느려질 수 있다. 대상 레포 2개라 최대 10초.

## ADR-006 상태줄 트랙 조각은 손댈 것만

- 상태: 제안
- 맥락: `--compact`가 끝난 worktree를 `끝N`으로 세고, 겹침도 끝난 worktree끼리까지 셌다(실측 `트랙 끝17 겹침50`).
- 결정: `--compact`는 ⛔ · 💤 · `진행N` · 진행 중 worktree끼리의 겹침만. 셋 다 0이면 빈 출력. 전체 표(옵션 없이)는 끝난 worktree를 「지울 worktree」로 따로 묶어 보여 준다.
- 결정 주체: 사람(문제) / AI 추천 수용(방법)
- 대안: `끝N`을 남기되 회색 — 여전히 할 일이 아닌 숫자다
- 결과: 끝난 worktree가 쌓여도 상태줄에는 안 보인다. 지우는 일은 지휘 §7 세션 끝 점검이 맡는다.

## ADR-007 검사 동시 실행은 "지금 도는 검사 프로세스 수"로 막는다

- 상태: 제안 (2026-10-31 개정 — 공식 문서 확인 뒤)
- 맥락: 전체 검사가 세 길(Stop 훅 · 러너 판정 · 모델이 직접 친 명령)에서 따로 돈다. 어디에도 동시 실행 상한이 없어 세션 17개가 동시에 돌았다(사람 관찰). 처음 안은 PreToolUse가 직접 친 명령 앞에 대기 래퍼를 끼우는 것이었는데, 공식 문서상 `updatedInput`(명령 바꿔 넣기)은 `allow`(자동 승인) 또는 `ask`(사람에게 묻기)와 짝이어야 한다. 플러그인이 사용자 권한 설정을 건너뛰어 자동 승인하거나, 검사마다 승인 창을 띄우게 된다.
- 결정: 잠금 파일을 두지 않고, 판단할 때마다 머신의 프로세스 목록(`ps`)에서 지금 도는 검사 명령 수를 센다. 검사 명령 = 현재 레포 `harness.json` verify 값들 + `pnpm verify`·`npm run verify`. 상한 `CLAUDE_VERIFY_MAX`(기본 2).
  - Stop 훅: 상한 이상이면 돌지 않고 `⏸ 다른 세션 검사 N개 중 — 건너뜀`
  - 러너 판정: 상한 아래로 내려갈 때까지 5초 간격으로 기다린다(최대 10분, 넘으면 그대로 돈다)
  - 모델이 직접 친 명령: PreToolUse가 상한 이상이면 차단(exit 2) + `다른 세션 검사 N개 중 — 30초 뒤 다시 실행` 안내. 명령은 바꾸지 않는다
- 결정 주체: AI 추천 수용
- 대안: 대기 래퍼 + `updatedInput` — 자동 승인 또는 매번 승인 창 / 잠금 파일 슬롯 — 직접 친 명령은 래퍼 없이 슬롯을 쥘 수 없고, 죽은 세션 슬롯 회수가 필요하다 / 공통 규칙 문구 — 모델이 빠뜨린다
- 결과: 셀 때와 시작할 때 사이 틈으로 상한을 1~2개 넘을 수 있다(17개가 몰리는 것은 막는다). 다른 레포의 검사 명령 문자열이 다르면 덜 센다 — `pnpm lint`·`turbo run` 같은 흔한 명령은 같이 잡힌다. 잠금이 없어 죽은 세션이 자리를 쥐는 일이 없다.
