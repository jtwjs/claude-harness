# 트랙 지시문 — <트랙 이름>

> 지휘 세션(`conductor` 스킬)이 채워 트랙 세션·서브에이전트에 넘긴다. 손으로 다시 쓰지 않는다.
> 값(모델명·시간·한도·enum)은 복사하지 않고 `ADR-NNN` 참조만 적는다 — 복사본은 정본이 바뀐 걸 따라오지 못한다.

| 항목 | 값 |

| 트랙 | `<이름>` (라벨 `track:<이름>`) |

| 계약 경로 | `<계약 파일>` (소비 트랙은 여기서 만든 생성 타입만 쓴다) |
| 완료 조건 | `.claude/harness.json` `verify` 중 자기 쪽 명령의 출력 |

## 열린 이슈 (`conductor` + `track:<이름>`)

| 번호 | 제목 | 선행(blockedBy) |
|---|---|---|
| #N | | #M (열림/닫힘) |

## 의존

- 선행 이슈가 열려 있는 step은 시작하지 않는다: <step → #이슈>

## 금지

- 소유 경로 밖을 고쳐야 하면 **멈추고 보고한다.** 판정은 지휘가 한다(승인 · 공유 구역 PR · 다른 트랙 후속)
- ADR 번호를 직접 매기지 않는다. 결정이 생기면 보고하고 지휘가 번호를 발급한다
- step 파일·지시문에 ADR 값을 복사하지 않는다

## 새 worktree 준비

```bash
git fetch origin
git worktree add ../<레포>-<트랙>-<주제> -b feature/<트랙>-<주제> origin/<기준 브랜치>
cd ../<레포>-<트랙>-<주제>
<의존성 설치 — 새 worktree 에는 node_modules 등이 없다>
```

## 끝나면 지휘에 보고

1. 끝낸 step · PR 번호
2. 새로 생긴 결정(있으면 한 줄씩 — 지휘가 `decision` 이슈로 만든다)
3. 계약 변경 여부(필드 추가 · enum · 의미 변경)
4. 소유 경로 밖 변경 요청(있으면)
5. 막힌 것과 무엇을 기다리는지
