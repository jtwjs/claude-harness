# 테스트 규칙

## 0. 무엇을 테스트하고 무엇을 안 하는가 (canonical)

**목표는 커버리지 수치가 아니라 회귀 위험 방어다.** "일단 다 테스트"는 금지 — 저가치 테스트는 리팩터를 방해하고 신호를 흐린다.

> ⚠️ 이 절은 `tdd-guard` 훅의 `tdd.exclude`와 **같은 내용을 가리켜야 한다.** 어긋나면 **막는 것과 적힌 것이 달라진다.**

**테스트한다 (필수)**
- **도메인 비즈니스 로직** — 상태 판정·정책·검증·파생 계산
- **기능당 통합 테스트 (대개 1개)** — 실제 사용 경로로 흐름을 검증. 회귀 비용이 큰 곳에 집중

**테스트하지 않는다**
- **목(mock)·픽스처 자체의 동작** — 목은 테스트 인프라다
- **얇은 전송 래퍼** — 그대로 넘기는 것이 전부인 코드. 동작은 통합 테스트가 커버
- **자명한 로직** — 게터, 상수 팩토리, 문자열·경로 빌더
- **도메인 무관 범용 유틸** — 단, *도메인 정책을 담은* 함수는 위 "필수"다. **이 경계로 구분한다**
- **상수·타입 선언·배럴 파일**, **개별 프레젠테이션 컴포넌트**(상위 통합이 흡수), **미러 복제 테스트**

**원칙 셋**
① 목을 테스트하지 않는다
② 한 로직을 여러 계층에서 중복 검증하지 않는다 — **가장 의미 있는 한 곳**에서
③ 구현 디테일이 아니라 **관찰 가능한 동작**을 단언한다

## 1. BDD 3계층

| 블록 | 의미 | 예 |
|---|---|---|
| `describe` | **Given** — 전제·상태 | `"로그인한 사용자"` |
| `context` (별칭 없으면 중첩 `describe`) | **When** — 조건·분기 | `"권한이 없는 경우"` |
| `it` | **Then** — 기대 결과만 | `"버튼이 비활성화된다"` |

- 🔴 **`Given:` / `When:` / `Then:` 접두는 붙이지 않는다.** 계층이 이미 의미를 드러내므로 접두 없이 위→아래로 **이어 읽히게** 쓴다.
- `context`는 「…인 경우」 / 「…할 때」처럼 **조건절로 끝낸다.**
- 한 줄에 셋을 몰아넣지 않는다.

> `context` 별칭은 러너의 `describe`에 이름만 붙인 것이다(대개 한 줄). 없으면 **만들지 말고** 중첩 `describe`로 같은 3계층을 세운다.

## 2. 엣지 5축 (테스트 작성 시 강제 훑기)

빈 값·경계 / 비정상 입력 / 실패 경로 / 상태 전이 / 동시성.
**축마다 해당 없으면 "해당 없음"이라고 적는다.** 조용히 건너뛰지 않는다.

## 3. 배치·격리

- 검증 대상과 **같은 디렉터리**에 둔다(colocation)
- 도구 간 확장자를 **혼용하지 않는다** — 단위·통합은 `*.test.*`, E2E는 `*.spec.*` 같은 식으로 하나를 정하고 지킨다
- 외부 경계(HTTP·시각·난수)는 **고정**한다. 테스트 간 상태가 새지 않게 격리한다

## 4. 🔴 목이 여러 개 필요하면 구조 문제다

출력 기반으로 못 쓰고 **목이 2개 이상** 필요하면, 그건 테스트가 아니라 **구현이 액션에 오염된 신호**다.

> 출력 기반 **>** 상태 기반 **>** 통신 기반(목). 목이 늘수록 테스트는 깨지기 쉬워진다.

케이스를 억지로 짜지 말고 보고한다 — 함수형 코어와 가변 쉘을 가르면 사라질 문제다.

## 5. RED 단계 — 구현 없이는 테스트 준비가 돌지 않는다

RED 테스트는 구현이 없어 **컴파일부터 실패**한다. 그래서 준비 코드(데이터 준비 · 헬퍼 · 픽스처 · 시간 한도)가 한 번도 돌지 않은 채 GREEN으로 넘어가고, GREEN 첫 실행에서 준비 코드 결함이 먼저 터진다. 구현 결함처럼 보여 재시도를 낭비한다(2026-10 병렬 트랙 실측: step 4곳에서 같은 일).

- RED 끝에 **준비 코드만 따로 한 번 실행해 본다**(구현을 부르지 않는 빈 테스트 하나로 픽스처 · 헬퍼만 돌린다)
- 통합 테스트의 INSERT · DELETE는 스키마 제약(NOT NULL · UNIQUE · 생성 컬럼)과 대조해 쓴다
- 프로세스 기동 · 컨테이너가 끼는 시간 한도는 실측 기동 시간보다 넉넉히
- 헬퍼 · 픽스처 이름이 서로 가리거나 겹치지 않게 한다
- GREEN 첫 실패가 준비 단계에서 났으면 구현보다 테스트 결함을 먼저 의심한다. 고칠 때는 준비만 고치고 단언은 바꾸지 않는다
