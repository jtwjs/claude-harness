# TypeScript 규칙

## `type` vs `interface`

| | 쓰는 곳 | 예 |
|---|---|---|
| **`type`** | **값·데이터의 모양**. 유니온·교차·유틸 조합 | API DTO, 응답 래퍼, 스토어 스냅샷, `Pick`/`Omit` 결과, `A \| B` |
| **`interface`** | **규격(contract)**. 경계에서 맞추는 약속 | 공개 컴포넌트 `*Props`, 훅 `Options`/`Return`, `implements` 할 포트 |

판별: **"이건 구현하는 관계인가, 그냥 모양인가?"** 구현·확장 관계가 있으면 `interface`.

## `any` 금지

- `any` 대신 `unknown` + 좁히기, 또는 제네릭.
- 외부 데이터(응답·파싱 결과)는 `unknown`으로 받아 **경계에서 검증**한다.
- 불가피하면 **그 줄에 이유를 주석으로** 남긴다. 이유 없는 `any`는 리뷰에서 🟡.

## 경계에서 좁힌다

타입은 **들어오는 지점에서** 확정한다. 안쪽으로 흘려보낸 뒤 여기저기서 좁히면 같은 검사가 반복되고 빠뜨리는 곳이 생긴다.

## 널 처리

옵셔널 체이닝으로 **덮지 말고** 왜 없을 수 있는지를 타입에 드러낸다.
`a?.b?.c ?? fallback`이 길게 이어지면 **모델이 잘못 잡힌 신호**다.
