# 함수형 설계 — 판정 6개

**FP의 목표는 부수효과를 없애는 게 아니라 분리하는 것이다.** 아래는 위반 여부를 가르는 판정만 적는다. 고치는 방법은 `references/`에 있다.

## 1. 액션 · 계산 · 데이터로 가른다

| | 뜻 | 다루기 |
|---|---|---|
| **액션** | 외부에 영향을 주거나 받는 것 | 어렵다 |
| **계산** | 입력 → 출력. 그뿐 | 쉽다 |
| **데이터** | 일어난 일의 기록 | 가장 쉽다 |

**판별 한 줄**: *"언제 호출하는지·몇 번 호출하는지에 따라 결과가 달라지면 **액션**"*
→ 현재 시각·난수·가변 객체 프로퍼티 읽기 전부 액션이다.

**구현 순서: 데이터 → 계산 → 액션.** 모양을 먼저 정하고, 그걸 다루는 계산을 짜고, 마지막에 액션으로 감싼다.

## 2. 액션은 전염된다

**액션을 부르는 함수는 액션이 된다.** 계산 안에서 액션을 부르지 않는다. 액션은 **가장 바깥으로** 민다.

## 3. 암묵적 입출력을 명시적으로

| | 명시적 | 암묵적 (← 이것을 줄인다) |
|---|---|---|
| 입력 | 함수 인자 | 전역·설정·현재 시각·외부 스코프 읽기 |
| 출력 | 반환값 | 전역 변경·로깅·저장·이벤트 발행 |

암묵적 입력은 **인자로 승격**, 암묵적 출력은 **반환값으로 바꿔 호출부로** 민다.

## 4. 숨은 입출력 3종

사이드이펙트 · **예외(`try/catch`)** · 내외부 상태 참조.

> 예외가 여기 들어가는 게 의외 포인트다. `try/catch`는 실행 흐름 자체를 바꾼다 — 던지기 전에 **실패를 값으로 반환**할 수 있는지 먼저 본다.

## 5. 카피-온-라이트

반환값을 직접 변이하지 않는다. 쓰기는 **복사본을 만들어 고치고 반환**한다.

⚠️ **중첩 전체가 불변이어야 불변이다.** 최상위만 상수로 선언한 것은 불변이 아니다.

## 6. 추상화 수준을 섞지 않는다

한 함수에 **도메인 규칙과 인덱스·반복문 조작**이 같이 있으면 분리한다.

> 판별: *"쓰는 쪽에서 어떤 자료구조인지 알아야 한다면"* 그건 낮은 계층이다.

- [ ] 테스트에 **목(mock)이 2개 이상** 필요해 보인다 → 패턴 1
- [ ] 함수 안에서 **전역·설정·현재 시각**을 읽는다 → 패턴 2·3
- [ ] **중첩 데이터를 수정**해야 한다 → 패턴 4
- [ ] **도메인 규칙과 인덱스·반복문**이 한 함수에 있다 → 패턴 5
- [ ] `try/catch`가 **실행 흐름을 바꾸고** 있다 → 패턴 6

⚠️ **도구가 목적이 아니다.** `map`/`filter`/`reduce`를 아무리 써도 *사람 생각에 가까운 코드*가 안 되면 이점이 없다. 특정 유틸 라이브러리를 강제하지 않는다.
