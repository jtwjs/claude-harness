# 멀티패러다임 · 함수형 설계

## 먼저 — FP를 쓸 자리인가 (적재적소)

FP는 기본값이 아니라 **계산 자리의 도구**다. 아래 OOP 자리에 FP를 억지로 입히지 않는다. 애매하면 한 줄: **"이게 상태를 쥐나?"** 쥐면 객체, 안 쥐면 함수.

| 이런 자리면 | 쓴다 | 없으면 나빠지는 것 | 예 |
|---|---|---|---|
| 입력 → 출력 계산 · 규칙 판정 · 변환 | FP 순수 함수 | 테스트에 목이 필요해지고 재사용이 막힌다 | 필터 · 집계 · `decide` |
| 수명 · 상태를 쥔 것 | OOP 객체에 캡슐화 | 상태가 인자로 새어 나와 호출부마다 관리한다 | API 클라이언트 · Spring 빈 · 커스텀 훅 |
| 만들 때 지킬 불변식이 있는 값 | 값 객체(생성 시 검증, 이후 불변) | 검증이 호출부마다 흩어진다 | `Email` · `Money` · 기간 |
| 종류는 고정 · 연산이 늘어남 | sealed · 판별 유니온 + `when`/`switch` | 연산마다 클래스를 고친다 | 결과(`Accepted`/`Rejected`) · 상태 |
| 종류가 늘어남 · 연산은 고정 | 인터페이스 + 구현 | 종류를 더할 때마다 모든 `when`을 고친다 | 알림 채널 · 결제 수단 |
| 바깥 세계와의 경계(DB · HTTP · 큐) | 인터페이스(포트) + DI | 계산이 인프라를 직접 안다 | Repository · 외부 API 어댑터 |

상속은 프레임워크가 요구할 때만(예외 계층 등). 재사용은 조합(함수 합성 · 위임)으로.

## 함수 3층 — 어디에 두나

| 층 | 무엇 | FE(FSD) | Kotlin | NestJS |
|---|---|---|---|---|
| 범용 계산 | 도메인을 모르는 작은 순수 함수. 이름이 곧 의도 | `shared/lib` | 최상위 · 확장 함수(파일명은 하는 일, `Util` 금지) | `shared/lib` 일반 함수 |
| 규칙 조립 | 범용 계산을 엮어 업무 규칙을 싣는다. 순수 · 단위 테스트 | `entities/<도메인>/model` | `domain/` | `domain/` |
| 액션 | 규칙을 불러 IO(호출 · 저장 · 발행)에 잇는다 | `features/<행동>` 훅 · 핸들러 | 서비스 | 서비스(provider) |
| 조립 | 액션과 결과를 배치만 | 컴포넌트 · 화면 | 컨트롤러 | 컨트롤러 |

- 순수 함수는 DI 대상이 아니다 — 빈(`@Component`) · `@Injectable`로 만들지 않는다. 현재 시각은 서비스가 `Clock`을 받아 인자로 넘긴다
- **읽기와 쓰기를 섞지 않는다(CQS)**: 값을 돌려주는 함수는 상태를 바꾸지 않고, 상태를 바꾸는 함수는 결과(결정 · id)만 돌려준다. 없으면: 조회라 믿고 부른 함수가 몰래 쓴다. 읽기 DB · 쓰기 DB 분리나 이벤트 소싱(풀 CQRS)까지는 가지 않는다
- 공용으로 올리는 기준: 3곳 이상에서 쓰면 범용 층으로. 1~2곳이면 쓰는 슬라이스 · 패키지 안에
- **호출 자리에는 이름 있는 함수 하나만.** 조건 · 여러 문장 · 변환이 들어가면 이름을 붙여 뺀다(계산이면 아래 층으로, 액션이면 핸들러로). 없으면: 같은 로직이 호출 자리마다 복사되고 테스트할 이름이 없다
  - ✅ `onChange={handleTitleChange}` · `onClick={() => remove(id)}` · `filter { it.active }`
  - ❌ `onChange={(e) => { …여러 줄… }}` · 분기 있는 여러 줄 람다(→ `private fun`) · 스코프 함수(`let` · `apply`) 중첩

## 함수형 설계 — 판정 6개

**FP의 목표는 부수효과를 없애는 게 아니라 분리하는 것이다.** 아래는 위반 여부를 가르는 판정만 적는다. 고치는 방법은 `references/`에 있다.

## 1. 액션 · 계산 · 데이터로 가른다

| | 뜻 | 다루기 |
|---|---|---|
| **액션** | 외부에 영향을 주거나 받는 것 | 어렵다 |
| **계산** | 입력 → 출력. 그뿐 | 쉽다 |
| **데이터** | 일어난 일의 기록 | 가장 쉽다 |

**판별 한 줄**: *"언제 호출하는지·몇 번 호출하는지에 따라 결과가 달라지면 **액션**"*
→ 현재 시각·난수·가변 객체 프로퍼티 읽기 전부 액션이다.

**구현 순서: 데이터 → 계산 → 액션.** 모양을 먼저 정하고, 그걸 다루는 계산을 짜고, 마지막에 액션으로 감싼다.

## 2. 액션은 전염된다

**액션을 부르는 함수는 액션이 된다.** 계산 안에서 액션을 부르지 않는다. 액션은 **가장 바깥으로** 민다.

## 3. 암묵적 입출력을 명시적으로

| | 명시적 | 암묵적 (← 이것을 줄인다) |
|---|---|---|
| 입력 | 함수 인자 | 전역·설정·현재 시각·외부 스코프 읽기 |
| 출력 | 반환값 | 전역 변경·로깅·저장·이벤트 발행 |

암묵적 입력은 **인자로 승격**, 암묵적 출력은 **반환값으로 바꿔 호출부로** 민다.

## 4. 숨은 입출력 3종

사이드이펙트 · **예외(`try/catch`)** · 내외부 상태 참조.

> 예외가 여기 들어가는 게 의외 포인트다. `try/catch`는 실행 흐름 자체를 바꾼다 — 던지기 전에 **실패를 값으로 반환**할 수 있는지 먼저 본다.

## 5. 카피-온-라이트

반환값을 직접 변이하지 않는다. 쓰기는 **복사본을 만들어 고치고 반환**한다.

⚠️ **중첩 전체가 불변이어야 불변이다.** 최상위만 상수로 선언한 것은 불변이 아니다.

## 6. 추상화 수준을 섞지 않는다

한 함수에 **도메인 규칙과 인덱스·반복문 조작**이 같이 있으면 분리한다.

> 판별: *"쓰는 쪽에서 어떤 자료구조인지 알아야 한다면"* 그건 낮은 계층이다.
